## Missed findings

- **M-add-1: Intra-line multi-match defeats the M2 4-tuple disposition key (a residual of M2 the Critic accepted as fully fixed).** The M2 fix keys disposition on `(relpath, normalized-line-context, fence-state, ordinal-among-identical-lines)` — the ordinal disambiguates *across identical lines*, never *within a line*. But the corpus has **24 lines carrying multiple matches (32 extra occurrences)**, including `skills/code-review/SKILL.md:103` with **5 distinct `architecture/` matches on one line** that need *different* classes (a `:(glob)architecture/*.md` pathspec → `rewrite-at-flip`, alongside prose `architecture/` mentions). All 5 share one identical `(relpath, normalized-line, fence-state, ordinal)` key, so rule 1 (disposition override) can only assign them ONE class — silently mis-classifying 4 of 5 (Wiegers, *Software Requirements* — the disambiguation requirement is incompletely specified; Hendrickson, *Explore It!* — the multi-occurrence-per-line edge case was not enumerated). The first Critic surfaced the *cross-line* collision (M2) but missed the *intra-line* one, and the accepted 4-tuple fix does not close it. **Proposed fix**: add `column-offset` (or match-ordinal-within-line) as a 5th key component, OR document per-line-multi-match co-classification and pin a `test_no_intra_line_ambiguous_multimatch` asserting no single line carries two matches needing different classes (today `code-review.md:103` would fail that test → forcing explicit disposition). Severity: **Major** (a real path silently dropped off the M4 checklist — the exact dangerous direction m2 names).

- **M-add-2: TF-1 test-first deviation from the directly-mirrored precedent, undocumented.** The slice sets `Test-first: false` (mission-brief line 6) for a deterministic context-aware classifier, while the tool it explicitly "mirrors" — `vault_flip_readiness_audit` — was built **`Test-first: true`** in BOTH slice-100 and slice-102, each with the recorded rationale *"per TF-1 — the classification logic is deterministic and naturally testable."* That rationale applies *more* strongly here: slice-107's classifier has NO AST to lean on, a fragile line-based fence-state detector, and the B2 mis-routing the Critic already caught — i.e. it is more defect-prone than the model, not less. TF-1 is opt-in (so the audit won't red on `false` — this is why it's not a Blocker), but the brownfield rule "Deviations need a written reason, not a judgment call" (CLAUDE.md) makes a silent `true→false` flip against the mirrored precedent a documented-convention deviation (Sommerville, *Software Engineering* — process-discipline conformance; McGraw — test-first is the cheapest place to prove a classifier non-vacuous). The first Critic checked AP-5 mutation-proofing (an after-the-fact pin) but never questioned the test-first flag itself. **Proposed fix**: either flip to `Test-first: true` with a `## Test-first plan` mapping each AC to a test (mirroring slice-100/102), OR record an explicit rationale in the brief / `risk-tier` for why this mirror-of-a-test-first-tool is exempt. Severity: **Major** (judgment / convention-conformance; no gate-red path, so not a Blocker).

- **m-add-1: Bare-`diagnose-out` (no-slash) mentions are absent from the documented residual.** The design's "documented residual" enumerates only the ~9 (real count: **7**) bare `graphify vault architecture` no-slash args, pinned by `test_bare_vault_dir_arg_residual`. But the corpus also carries bare `diagnose-out` (no-slash) prose/arg mentions (e.g. `skills/slice/SKILL.md:73` "MUST consult diagnose-out", `slice-candidates/SKILL.md:4` "omit to use ./diagnose-out") that name the vault location and are invisible to any slashed match — symmetric to the `architecture` bare-arg residual but unenumerated. Low confidence on magnitude (most bare `diagnose-out` hits are slash-suffixed or in `.py` out-of-surface files) — **Builder should grep `\bdiagnose-out\b` not followed by `/` across the 5 prose globs and either fold the operational ones into the residual list or confirm the set is empty.** Severity: **Minor**.

## Severity adjustments

- **B1 — VALID conclusion, but the EVIDENCE is wrong and must be corrected before it propagates into the baseline pin (AP-2: a fix is a fresh claim).** The Critic's B1/B3 report "anchored `_SLASHED_RE` = 285, gap = 33." Executed against the real corpus, the *actual* `_SLASHED_RE` (delimiter class `[\s'"(/=]`, which contains **no backtick**) matches **69**, not 285; the real gap is **249** (216 backtick-preceded inline-code + 32 `)`-preceded + 1 `{`-preceded), not 33. The 285 number is reproducible *only* by adding a backtick to the delimiter class (`69 + 216 backtick = 285` exactly — confirmed), i.e. the Critic implicitly assumed the anchored regex already catches inline-code `` `architecture/…` `` paths. It does NOT. Consequence: the design (line 33) and brief still assert "the anchored `_SLASHED_RE` would have reported only ~285 — the 33-literal gap" — both numbers are wrong; the true under-count would have been ~249. This is not severity-mis-filing of B1 itself (still a Blocker) but a **correctness defect in the accepted B1 evidence** that the Builder must fix in design.md §Match rule + §Prose surface + mission-brief AC1 before the baseline is pinned, or the slice ships a documented-but-false gap arithmetic. (It does not change the *fix* — boundary-free 318 is right — only the stated magnitude.)

- **B3 — same evidence defect, same direction.** B3's "anchored ~285 contradicts grep ~318" is the *under*-statement of a 318-vs-69 contradiction. The B3 *resolution* (tool count == grep count ≈ 318) is correct, but its premise number (285) is wrong. Additionally, a **latent B3 residue the Critic did not price**: the design asserts "the tool's occurrence count **equals** the grep count" and the smoke gate asserts `tool == grep -rohE ≈ 318`. This holds ONLY if the tool scans with `re.finditer`/`findall` (all matches per line/file). If the line-based classifier does a per-line single `re.search` (one match per line — a natural implementation given the design's pervasive "the literal's line" / line-context framing and the line-keyed M2 disposition model), it reports **286** (lines-with-match), undercounting by 32 and *failing its own smoke gate*. The design's occurrence-model vs line-key-model is under-specified for intra-line multiplicity (this is the same root cause as M-add-1). **Builder must specify all-matches-per-line scanning explicitly** and the smoke gate should assert `tool == 318`, not just "agrees with grep." Severity of this residue: **Major** (would either fail the gate or mask the B1 hole). Folded into M-add-1's fix.

Medium-high confidence on M-add-2 (TF-1) — it is a judgment/convention finding (TF-1 is opt-in so no gate reds), defensible to override at TRI-1 if the user accepts inventory-tools-are-baseline-pinned-not-test-first as a deliberate standing policy, but the *direct* slice-100/102 mirror makes the silent flip worth surfacing. Lower confidence on m-add-1 (bare-`diagnose-out`) — flagged for Builder verification, not asserted. **Calibration observation on the first Critic's pattern this slice**: the Critic executed against the real corpus (APED-1, commendable) but made a single high-leverage measurement error — treating the backtick as a `_SLASHED_RE` delimiter — that simultaneously (a) understated B1's gap 7×, (b) understated B3's contradiction, and (c) hid that the 216 backtick inline-code paths were *never matched by the anchored regex at all* (the Critic framed the 119 B2 paths as "matched-but-mis-classified," when in truth they were *unmatched* under the original anchored design — B1 and B2 overlap far more than the critique implies). The fixes still land correctly because boundary-free + fail-closed `needs-human` subsumes the whole 249, but the slice's *documented arithmetic* is wrong and one disambiguation class (intra-line) remains open. Disjointness from slice-106, M1, M3, and the fail-closed architecture are all sound and survived re-attack.

**Verdict: EXTEND** — two missed Majors (M-add-1 intra-line multi-match, M-add-2 TF-1 deviation), one missed Minor (m-add-1 bare-`diagnose-out`), plus a correctness defect in the accepted B1/B3 evidence that must be fixed before the baseline is pinned.
