# Design: Slice 087 add-stranded-slice-detection-to-slice

**Date**: 2026-05-30 (reframed 2026-05-31)
**Mode**: Standard

> ## ✅ REFRAMED — parallel-safe **4-class divergence model** applied (2026-05-31)
>
> **History.** After `/critique` + `/critique-review` (NEEDS-FIXES, all 7+2 findings reconciled), the USER caught a flaw neither Critic layer reached: the pre-reframe detector flagged **ALL** unmerged `slice/*` branches/worktrees as "stranded." But under the project's parallel-slice execution model (PSQ-1 / PSQ-2 / BRANCH-2), **many concurrent unmerged `slice/*` is the NORMAL state** — so an existence-based detector would cry-wolf on every in-flight parallel slice at every `/slice` open → the R-7 silent-disable class (a noisy gate gets ignored) AND it actively undermines the parallel-slice direction. (This miss motivated the `agents/critique.md` **Dim-7 strategic-direction-fit + architectural-concurrency** probe, committed `64f6ea3`; re-running `/critique` on this reframed design is that probe's first live test.)
>
> **Resolution — classify, don't flag-all.** "Stranded" is not "an unmerged branch exists"; it is a git-vs-vault **divergence** where the vault believes the work is DONE (the slice-086 bug) or there is git work with NO vault story at all. The detector CLASSIFIES every unmerged `slice/*` branch into one of **four divergence classes** (+ INDETERMINATE for fail-closed unknowns) and **halts `/slice` only on the two genuine-divergence classes**. A healthy in-flight parallel slice (its own worktree, milestone mid-stage) classifies as **IN-PROGRESS → informational, never halts.** See `## Classification model` below. The flag-all (existence-based) approach is recorded as the **rejected Option 4** in [[ADR-079]].
>
> **What the reframe costs (and saves).** The model needs **vault state** (per-slice `milestone.stage` + `archive/` presence) and **PSQ-2 claims** (`slice-queue.md`) cross-referenced against git — a bigger contract than the pre-reframe git-only design. But the cost is contained by reuse: slice-077's `pulse_worktree_resolver.classify_worktree_state` **already** computes the 4-state `WorktreeState` taxonomy (`IN_PROGRESS` / `BUILT_BUT_NOT_MERGED` / `MERGED` / `UNKNOWN`) for any branch that has a live worktree, and `slice_queue_claim.parse_queue_text` already parses PSQ-2 claims. The genuinely-new code is the **bare-branch (no-worktree) classification** + the **claim cross-reference** + the **`/slice` halt-only-on-divergence gate** — strictly smaller than re-deriving any of the reused machinery.

> **Post-critique reshape (B1/M3) — preserved and STRENGTHENED.** slice-077's `tools/pulse_worktree_resolver.py` ALREADY detects `slice/*` worktrees AND classifies their state. This slice does NOT re-implement that — it **reuses both `detect_active_worktrees` and `classify_worktree_state`**, and its genuine-new value is the bare-unmerged-`slice/*`-branch-WITHOUT-a-worktree case, the PSQ-2 claim cross-reference, and the `/slice`-open consult (the residual R-22's `/pulse`-only mitigation left open).

## Classification model (4-class divergence + INDETERMINATE)

The detector enumerates every **unmerged** local `slice/NNN-<name>` branch (`git for-each-ref refs/heads/slice/` minus branches that are ancestors of the default branch) and classifies each by the precedence below. **Precedence is load-bearing** — a branch can satisfy more than one condition (e.g. vault-done AND claimed-by-another), and the order decides which class (and therefore whether `/slice` halts) wins.

| # | Class | Condition (first match wins) | `/slice` behavior | `halt` |
|---|-------|------------------------------|-------------------|--------|
| 1 | **CLAIMED-BY-OTHER** | PSQ-2 `slice-queue.md` carries a `**Claimed-by:** <name> <email>` for the candidate key `<name>` derived from the branch (`slice/NNN-<name>` → queue key `<name>`) whose git identity ≠ my `git config user.name`+`user.email` | informational — `"owned by <name>"` | no |
| 2 | **IN-PROGRESS** | the branch has a live worktree whose `classify_worktree_state` = `IN_PROGRESS` (milestone stage ∈ {slice…validate}), OR the current tree's active `slices/slice-NNN-*/milestone.md` stage is non-terminal | informational — `"parallel slice in flight"` | no |
| 3 | **STRANDED-COMPLETE** | git-unmerged **AND** vault says DONE: worktree `classify_worktree_state` = `BUILT_BUT_NOT_MERGED` (stage=reflect, HEAD not ancestor), OR `archive/slice-NNN-*` exists in the current tree, OR the current-tree milestone stage is terminal / `next-action` = commit | **HALT** with options (the slice-086 bug) | yes |
| 4 | **ORPHANED** | git-unmerged AND **no** vault story anywhere (no live worktree, not in `archive/`, no active milestone, no PSQ claim) | **HALT** with options | yes |
| 5 | **INDETERMINATE** | classification could not complete: `classify_worktree_state` = `UNKNOWN` (e.g. malformed milestone, `merge-base-error`), OR a per-branch `merge-base --is-ancestor` returned a non-0/1 error | **HALT**, surfaced with the specific sub-reason | yes (fail-closed) |

**Why CLAIMED-BY-OTHER outranks STRANDED-COMPLETE (precedence #1 over #3).** If another git identity committed-but-didn't-merge a slice, that is *their* stranded work and they may be mid-merge; halting *my* `/slice` over it is exactly the cross-session cry-wolf the reframe exists to kill. So a branch claimed by another identity is always informational. For the **solo-dev case this repo actually is** (one git identity — see `triage.md`), claims are by *my* identity, so CLAIMED-BY-OTHER never fires and a vault-done-but-unmerged branch correctly surfaces as STRANDED-COMPLETE. CLAIMED-BY-OTHER is the multi-session generalization PSQ-2 already provisions for; it is cheap to include because `parse_queue_text` + the git-identity read already exist (zero new parsing).

> **Claim-resolution honesty (B1 — re-`/critique` finding, executed against the live queue).** `slice-queue.md` keys entries by `### <candidate-name>` and PSQ-1's writer regenerates it from the *backlog top-10*, so an **in-flight slice's candidate is frequently ABSENT from the queue** (verified live: `add-project-frame-synthesizer` is not a queue key, and every present entry has no `Claimed-by`). The branch→key mapping is `slice/NNN-<name>` → `<name>`; when that key is **absent OR present-but-unclaimed**, CLAIMED-BY-OTHER simply does not match and the branch falls through to precedence #2/#3/#4 — **this is CORRECT behavior, not a silent miss** (the parallel-safety signal for an in-flight branch is IN-PROGRESS via its live worktree, precedence #2, which the re-`/critique` confirmed fires against the live `slice/087`+`slice/088`). CLAIMED-BY-OTHER fires **only** when the queue carries a claim for `<name>` by a *different* identity — the genuine multi-session race. Two consequences this design accepts honestly: (1) in solo-dev + the current PSQ-1 regeneration lifecycle the class is **largely inert** (it is a forward-provision, not a load-bearing solo-dev path — the load-bearing parallel-safety class is IN-PROGRESS); (2) AC4(d)'s fixture proves the *code path* with a synthetic queue (`### <name>` = branch suffix + a foreign `Claimed-by`), and the design states plainly that production reachability depends on PSQ-2 carrying an in-flight claim for that key — see AC4(d) note in mission-brief. *(If the user prefers, the declinable alternative at TRI-1 is to demote CLAIMED-BY-OTHER to an explicitly-deferred follow-on and ship a 3-active-class model — STRANDED-COMPLETE/ORPHANED halt, IN-PROGRESS informational, + INDETERMINATE — which is simpler and loses nothing in solo-dev.)*
>
> **Claim-key collision residual (M2 — code-review, acknowledged).** The branch→key mapping is lossy by design: it discards the slice number (`slice/NNN-<name>` → `<name>`) because PSQ-1's queue itself keys candidates by the bare `<name>`. Consequence: a genuinely-stranded `slice/400-foo` could be downgraded to CLAIMED-BY-OTHER (no halt) by a *foreign* claim on key `foo` originating from an unrelated `slice/600-foo` candidate — a precedence-#1-over-#3 downgrade. This is **inert in solo-dev** (CLAIMED-BY-OTHER never fires — one identity) and bounded by PSQ-1's own bare-name keying scheme, so it is accepted as a known residual rather than fixed here. If PSQ keys ever gain slice numbers, key claims by `<NNN>-<name>` to close it.

**Why IN-PROGRESS outranks STRANDED-COMPLETE (precedence #2 over #3).** This is the actual parallel-safety fix. A slice with a live worktree at stage ∈ {slice…validate} is healthy in-flight work; `classify_worktree_state` returns `IN_PROGRESS` *without consulting ancestry* (per ADR-070 — a pre-reflect slice's ancestry is irrelevant). Such a branch must never halt `/slice`. Only once a worktree reaches stage=reflect-and-unmerged does it become `BUILT_BUT_NOT_MERGED` = STRANDED-COMPLETE.

**Top-level `status`.** `clean` ⟺ zero halt-worthy entries (classes 3/4/5). IN-PROGRESS and CLAIMED-BY-OTHER entries are **listed** (for `/pulse` to surface and for transparency) but do **not** make the run `divergent`. `divergent` ⟺ ≥1 entry with `halt: true`. `/slice` halts only when `status == divergent`.

## What's new

- **`tools/stranded_slice_audit.py`** — a new read-only git-vs-vault **classifier** (not an existence-flagger). It:
  - **Reuses** `pulse_worktree_resolver.detect_active_worktrees` (worktree enumeration) + `pulse_worktree_resolver.classify_worktree_state` (the 4-state `WorktreeState` taxonomy) for every `slice/*` branch that HAS a live worktree — mapping `IN_PROGRESS`→IN-PROGRESS, `BUILT_BUT_NOT_MERGED`→STRANDED-COMPLETE, `MERGED`→skip, `UNKNOWN`→INDETERMINATE.
  - **Adds the bare-branch case** (the genuinely-new value): `git for-each-ref refs/heads/slice/` minus branches already reported via worktrees → for each remaining, `git merge-base --is-ancestor <branch> <default>` (ancestor ⇒ merged, skip; non-ancestor ⇒ candidate) + ahead-count `git rev-list --count <default>..<branch>`. A bare unmerged branch is then classified by reading **the branch's OWN tree, not (only) the invoking tree** (M1 — re-`/critique` finding): the stranded archive/milestone state of a committed-but-unmerged slice lives *on the unmerged branch by definition*, so the lookup is `git ls-tree <branch> -- architecture/slices/archive/slice-NNN-*` (archived ⇒ STRANDED-COMPLETE) and `git show <branch>:architecture/slices/slice-NNN-*/milestone.md` (parse stage: terminal/next-action=commit ⇒ STRANDED-COMPLETE; non-terminal ⇒ IN-PROGRESS) — falling back to the invoking tree only as a secondary source. The invoking-tree-only lookup would MISS the canonical slice-086-class incident (archive committed solely on the stranded branch) and mislabel it ORPHANED, handing the operator the wrong recovery affordance. PSQ claim for `<name>` by another ⇒ CLAIMED-BY-OTHER; no vault story on the branch's tree, the invoking tree, or the queue ⇒ ORPHANED. A per-branch merge-base **error** ⇒ that entry is `INDETERMINATE` (mirror `pulse_worktree_resolver`'s `merge-base-error` UNKNOWN), NOT a whole-run failure (m2).
  - **Adds the PSQ-2 claim cross-reference**: reuse `slice_queue_claim.parse_queue_text` to read `architecture/slice-queue.md` claims + read my identity via `git config user.name`/`user.email`; map the branch to a queue key (`slice/NNN-<name>` → `<name>`); a claim under that key whose identity ≠ mine ⇒ CLAIMED-BY-OTHER (precedence #1). **Key-absent OR present-but-unclaimed ⇒ class does not fire ⇒ correct fall-through to #2/#3/#4** (NOT a silent miss — see the Claim-resolution honesty note in `## Classification model`). Claim parsing absence/failure is non-fatal (no `slice-queue.md` ⇒ no claims ⇒ that class simply never fires).
  - **Output**: each entry is `{branch, worktree_path | null, klass, halt, vault_state, claimed_by | null, ahead, dirty, reason}` where `klass ∈ {stranded-complete, orphaned, in-progress, claimed-by-other, indeterminate}`. Top-level `status ∈ {clean, divergent}` (divergent ⟺ ≥1 `halt: true`). Exit 0 + `status: clean` when no halt-worthy entries; exit 0 + `status: divergent` + entries when found (advisory — NOT a refuse; **no exit 1**). Exit 2 only on usage failure (git unavailable, default-branch unresolvable, bad root). `--json` + human; accepts `--repo-root` AND a `--root` alias with default-mode = detection so the `_ROOT_ONLY_TOOLS` cp1252 regression genuinely reaches stdout (M2); UTF8-STDOUT-1 compliant (`_stdout.reconfigure_stdout_utf8()` first statement of `main()`). **Non-vacuous cp1252 guard (M3 — re-`/critique` finding)**: the `_ROOT_ONLY_TOOLS` test only guards UTF8-STDOUT-1 if the `[-m tool, --root, REPO]` run emits a non-ASCII char; an all-`clean`/empty fixture would print only ASCII and pass vacuously (the slice-085 incidental-pass lesson). So the **human-mode summary header always emits a `→`** (e.g. `stranded-slice-audit → status: clean (0 divergent)`), independent of entry count, making the cp1252 test non-vacuous on any fixture; build-time verification confirms the fixture run reaches that glyph.

Proceed-anyway is always offered on the gate (advisory, never blocking). On exit 2 (usage), surface the stderr and continue (fail-visible, not fail-silent skip).

## Error model for this slice

- Detector: exit 0 (`status: clean|divergent`); exit 2 on usage failure (git binary unavailable, default-branch unresolvable, root not a git repo) with a stderr message (NAW-1 fail-visible precedent). There is **no exit 1** — divergence is informational, never a hard failure. A single branch's `git merge-base --is-ancestor` **error** (non-zero-non-1), a `classify_worktree_state` = `UNKNOWN`, or a malformed milestone marks that entry `INDETERMINATE` (halt-worthy, fail-closed, surfaced with the specific sub-reason) and the run still succeeds (m2; mirrors `pulse_worktree_resolver`'s `merge-base-error` UNKNOWN) — it does NOT escalate to a whole-run exit 2.
- **Fail-closed on ambiguity**: INDETERMINATE is `halt: true` deliberately. An entry the detector cannot confidently classify must surface (the R-7 silent-disable class is the failure mode we are avoiding), and proceed-anyway is always available, so a fail-closed halt costs at most one extra prompt. Silently dropping an unclassifiable branch is the one outcome the design forbids.
- `/slice`: on detector exit 2, surface the stderr and continue (do not silently skip — R-7 silent-disable class); on `status: divergent`, HALT with the structured-options gate; on `status: clean` with informational entries, surface a one-line note and proceed (no gate).
- **Self-reference / in-flight classification (m-add-1) — reconciled under the 4-class model**: the active slice's OWN `slice/NNN` branch becomes a bare-unmerged-branch-without-worktree after `/commit-slice --push` (awaiting PR) or a `--merge` worktree-remove failure (both live states per risk-register R-22 lineage). After `--push` the slice has typically been reflected/archived, so the current-tree vault says DONE ⇒ the branch classifies **STRANDED-COMPLETE** ⇒ HALT-with-Resume. This is **EXPECTED, not a false positive**: the gate's Resume / `--sync-after-pr` options frame the awaiting-PR branch correctly as resumable. The crucial contrast with the pre-reframe flaw: a *healthy in-flight* parallel slice (own worktree, mid-stage) is **IN-PROGRESS**, which the reframe makes informational — so it no longer cry-wolfs. AC4 case (h) pins the own-pushed-branch STRANDED-COMPLETE behavior; AC4 case (c) pins the IN-PROGRESS no-halt behavior (the central parallel-safety property).
- **`recovery/*` exclusion mechanism (m-add-2)**: enforced **structurally by the `git for-each-ref refs/heads/slice/` ref-glob** (`recovery/*` lives at `refs/heads/recovery/...`, outside the glob) — NOT a post-filter. The glob is **load-bearing**: widening it to `refs/heads/` would silently reintroduce `recovery/*` false-positives.
- **Orphan ahead-count (m-add-2; m1 prose correction)**: for a branch sharing no common ancestor with default, `git merge-base --is-ancestor` returns exit 1 (not an error) so the branch correctly classifies as non-ancestor→candidate→ORPHANED; `git rev-list --count <default>..<branch>` does *not* error and *does* return a count (all branch commits) — it is **defined but not meaningful** as "commits ahead of a shared base" (the earlier "undefined-symmetric" wording was wrong). We set `ahead: null` to signal "no shared base" distinctly from a numeric ahead-count, and distinctly from INDETERMINATE (which is reserved for a genuine merge-base *error*, exit non-0/1).
- **Bare-branch vault read is committed-tip state, NOT working-tree state (M-add-1 — dual-review missed finding).** The M1 bare-branch lookup (`git ls-tree <branch> -- …archive/…` / `git show <branch>:…/milestone.md`) reads only what is **committed** on the branch tip. For a branch WITH a live worktree this never matters — precedence #2's `classify_worktree_state` reads the on-disk *working-tree* `milestone_path` (`pulse_worktree_resolver.py:331-334`). But the bare-branch path is precisely where the working tree is gone, so committed-tip is the only recoverable state. The canonical slice-086 incident is the benign sub-case (archive WAS committed before the worktree died). The adversarial sub-case: a worktree removed (partial `--merge` cleanup, R-22 lineage) *after* the slice reached reflect/archive on disk but *before* that terminal milestone/`archive/` move was committed → `git show <branch>:` returns a pre-reflect/pre-archive stage → STRANDED-COMPLETE silently **downgrades** to IN-PROGRESS or ORPHANED → a weakened/absent halt on a genuine-divergence branch. The design **accepts and names** this staleness: (a) a bare branch has no working tree, so committed-tip is the only ground truth available — there is no stronger source to read; (b) the fail-closed posture still surfaces *something* (a downgrade to ORPHANED still halts; only a downgrade to IN-PROGRESS goes silent, and that requires the narrow "reflect-reached-on-disk-but-uncommitted-AND-worktree-removed" window); (c) the error model does NOT assume `git show <branch>:` is current truth. AC4 case for the uncommitted-terminal-milestone window is documented as a known residual (not a silent assumption) — the Builder must decide at build whether to add a dirty-at-removal caveat or accept the residual; either way the staleness is named here, not assumed away.
