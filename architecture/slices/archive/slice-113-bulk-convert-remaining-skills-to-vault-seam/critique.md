# Critique: Slice 113 bulk-convert-remaining-skills-to-vault-seam

**Critic reviewed**: mission-brief.md, design.md, ADR-106, project-frame.md (+ grounded against live `tools/vault_flip_prose_inventory.py`, `test_vault_flip_op_gate.py`, `test_vault_flip_prose_inventory.py`, `test_bcr_1_backlog_round_trip.py`, `test_validate_slice_skill.py`, `test_build_slice_skill_dirty_tree_resolution.py`, `test_slice_skill_drift.py`, and `--json` / `--op-gate --json` real-corpus output)
**Date**: 2026-06-04
**Result**: NEEDS-FIXES (Critic recommendation; final verdict computed from ratified dispositions at Triage)

## Summary

The core mechanism (seam-aware op-gate + move-together inventory re-pin + carve-out ratchet) is sound and grounded, and the ADR-105 carve-out taxonomy is applied correctly. But the design (a) misses at least two by-name `architecture/...` literal-path consumer tests that conversion breaks or threatens (`test_validate_slice_skill.py`, `test_build_slice_skill_dirty_tree_resolution.py`) — the exact AP-13 / FBCD-1(c) / PTFFD-1 class; (b) under-specifies the value-extractor half of the op-gate seam change (`_PATH_TOKEN_RE` twin), which — if missed at build — silently re-routes every converted active-folder write to OP_UNROUTED, with zero existing test coverage to catch it (AP-5); and (c) leaves 4 agent files + INSTALL.md + README.md carrying convertible operational refs while claiming "R-32's only residual is the physical move," which is false.

#### B2: Op-gate value-extractor (`_PATH_TOKEN_RE` → `_OP_SINK_TOKEN_RE`) is the load-bearing half of the seam change, but the design under-specifies it and there is zero `<vault>/`-sink test coverage to catch a miss (AP-5 non-vacuity)
- **Claim under review**: ADR-106 DECISION: "`_OP_SINK_RE` … used by `scan_op_file`. The op-gate's classification sub-regexes … are prefix-agnostic and unchanged." design.md §1: "`scan_op_file` uses these INSTEAD of inventory `_MATCH_RE`/`_PATH_TOKEN_RE`."
- **Issue**: `_classify_op` keys on the op's **sink VALUE**, not the line (`_ACTIVE_FOLDER_RE.search(sink)`, `_UNDECIDED_DISPOSITION_RE.search(sink)` — `tools/vault_flip_prose_inventory.py:543,547`). `scan_op_file` extracts that value via `_PATH_TOKEN_RE.match(line, col)` at `:592`. Executed: with `_OP_SINK_RE` as matcher but `_PATH_TOKEN_RE` as extractor, a `<vault>/risk-register.md` sink matches at the `<vault>/` column, but `_PATH_TOKEN_RE.match` returns None there → the value falls back to `m.group(0)` = bare `"<vault>/"` (path tail LOST). Then `_ACTIVE_FOLDER_RE.search("<vault>/")` is False → a converted `<vault>/slices/slice-NNN/...` write no longer classifies DEFERRED; it falls through to `OP_UNROUTED` for every converted active-folder write in an in-loop skill. ADR-106's DECISION only mentions `_OP_SINK_RE` and is silent on the extractor; design.md mentions `_OP_SINK_TOKEN_RE` but does not state that value-extraction governs classification, nor that the two MUST move together. The 40 op sinks include 11 DEFERRED active-folder writes — every one is at risk if the extractor isn't upgraded.
- **Evidence**: `tools/vault_flip_prose_inventory.py:543,547,592`; executed reproduction (bare-`<vault>/` value → `_ACTIVE_FOLDER_RE` miss). `test_vault_flip_op_gate.py` has NO test exercising a `<vault>/` sink — every fixture uses `architecture/...` (lines 47-242). So a value-extractor miss passes the entire op-gate suite vacuously and only surfaces as the real-corpus `--op-gate --strict` going red at build (or going green-by-coincidence if no converted active-folder line exists, then failing on the next slice).
- **Proposed fix**: (1) State in ADR-106 CONSEQUENCES that `scan_op_file`'s value extractor MUST be upgraded to `_OP_SINK_TOKEN_RE` in lockstep with `_OP_SINK_RE`, and that the extracted VALUE drives `_classify_op` — both required for the prefix-agnostic-classification claim. (2) Add op-gate tests with `<vault>/`-prefixed sinks proving: a converted `<vault>/slices/slice-NNN/...` in-loop write → OP_DEFERRED_TO_FLIP; a converted `<vault>/slice-queue.md` → OP_OUT_OF_SCOPE; a converted in-loop un-routed `<vault>/risk-register.md` write → OP_UNROUTED. The AP-5 non-vacuity mutation tests the mid-slice smoke gate gestures at but no test encodes. (3) Build-step EXECUTES `--op-gate --strict` after conversion AND asserts the per-class breakdown is still {6,11,23,0}, not just exit 0.
- **Builder draft**: **ACCEPTED-FIXED** (ADR-106 + design + new tests pinned as build deliverables). This is the headline catch — the AP-4 code-Critic class the design+meta reasoning structurally missed ("prefix-agnostic sub-regexes, no change needed" glossed that the *extractor* feeding them is the gap). Correction: `_OP_SINK_TOKEN_RE` extractor is **co-load-bearing** with `_OP_SINK_RE` and they move in lockstep; `_classify_op` consumes the extracted VALUE. Add the 3 `<vault>/`-sink op-gate tests (DEFERRED active-folder / OUT_OF_SCOPE slice-queue / UNROUTED bite) as the AP-5 non-vacuity proof — these also prove ADR-106's forward-protection claim is real (an un-routed `<vault>/` in-loop write reds), which today is *unproven*. Build asserts the {6,11,23,0} per-class breakdown, not just exit 0. NOTE for triage: in THIS slice's corpus the active-folder sinks stay concrete (carve-outs), so the extractor bug fails **closed** (over-flags as OP_UNROUTED) rather than open — but ADR-106's whole claim ("the op-gate handles `<vault>/` sinks") is **false** without the extractor upgrade, so it MUST land here.

#### M3: Carve-out ratchet keying `(path, sha256(value))` cannot distinguish class-4 `<wt_path>/architecture/...` from a same-suffix convertible literal in the same file — weakens the slice/SKILL.md ratchet
- **Claim under review**: design.md §4: "_CONVERTED_CARVEOUTS grow with each file's residual carve-out literals (classes 4/5/6/7), hash-keyed (path, sha256(value))." Must-not-defer: "skills/slice/SKILL.md is the canonical case."
- **Issue**: `_MATCH_RE` is boundary-free on `architecture/` — it strips any `<wt_path>/` prefix, so the recorded `value` for a class-4 composed path `<wt_path>/architecture/slices/slice-NNN-<name>/mission-brief.md` is `architecture/slices/slice-NNN-<name>/mission-brief.md` (verified slice/SKILL.md:267). Because the carve-out allowlist is keyed `(path, sha256(value))`, a single carve-out entry for the class-4 value would ALSO whitelist any future regressed literal in slice/SKILL.md sharing that value — the ratchet can no longer tell "legitimate class-4 `<wt_path>/` concrete" from "regressed bare `architecture/` operational." `converted_file_regressions` (`:362-373`) gates value-only, no line/column/prefix discrimination. So slice/SKILL.md ratchet protection is materially weaker than CLAUDE.md's (where carve-out values are unique diagnose-out paths).
- **Evidence**: `tools/vault_flip_prose_inventory.py:95` (boundary-free `_MATCH_RE`), `:358-373`; `--json` slice/SKILL.md values at lines 3, 249, 267, 268.
- **Proposed fix**: Acknowledge the limitation in design.md and choose: (a) accept + document that slice/SKILL.md class-4 carve-outs collapse same-value literals, OR (b) strengthen `_CONVERTED_CARVEOUTS` keying to the disposition 5-tuple for class-4 sinks. At minimum add a ratchet mutation test that injects a bare `architecture/slices/slice-NNN-<name>/mission-brief.md` into slice/SKILL.md and proves the ratchet still fires despite the same-value class-4 carve-out (the AP-5 non-vacuity proof for the canonical case the must-not-defer names).
- **Builder draft**: **ACCEPTED-FIXED** — design records the limitation + a build-time discrimination + a mutation test. At build, after the carve-out set settles, check whether any *convertible* literal shares a `(path, value)` with a class-4/5 carve-out in the same file: **if a real collision exists → strengthen that file's carve-out keying to the disposition 5-tuple** (option b — the ratchet stays strong); **if not** → document the same-value-collision limitation (option a) and add a **differing-value** ratchet mutation test on slice/SKILL.md proving non-carved-value regressions still fire.
