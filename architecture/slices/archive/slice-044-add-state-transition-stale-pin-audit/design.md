## What's new

- `tools/state_transition_pin_audit.py` — new audit-enforced pre-finish gate (RULE-ID **STP-1**, NON-`-D` `vN.N`, audit-gate naming-class peer of BRANCH-1 / BC-1 / PMI-1 / UTF8-STDOUT-1 / CRP-1 / PCA-1 / BCI-1 / MCFS-1). Two independent sub-form detectors:
  - **Sub-form A — SKILL.md-prose-repoint stale pin** (R-10's exact class; *git-diff-INDEPENDENT standing invariant*). Mechanism (revised post-critique B1/B2/B3):
    - **Binding tracer** (B2 fix): for each `tests/**/test_*skill*.py`, AST-resolve every local OR module-level name transitively bound — directly or through a `str.split(<lit>, …)[i]` / subscript / slice chain — from a `read_file("skills/<x>/SKILL.md")` call (bare imported `read_file` only; see What's reused). Each traced name maps to its origin SKILL.md path. Both the dominant function-local `content = read_file(…)` + sliced-segment (`prereq_block = content.split("## …")[1]…`) shape AND the module-level `BUILD = read_file(…)` shape are covered.
    - **Positive-membership only — `and`-per-operand, `or`-excluded** (B1 fix + B-add-1 relocation fix + **Task-1 self-verify `Or`-disjunction refinement**): a candidate pin is any `ast.Compare` whose single op is `ast.In`, left operand a statically-constant (post-fold) string, right operand a traced SKILL.md-bound name (or sliced sub-segment). A node is excluded when (i) its own op is `ast.NotIn`; OR (ii) it is an operand of an **`ast.Or` BoolOp** — a *disjunction* pins NO single operand individually-present (`assert "solo-dev" in c or "solo dev" in c` legitimately has one absent alternative; per-operand flagging is a false positive — caught by STP-1's own Task-1 self-verification on the live repo, a class the dual-Critic+DR-1 stack missed); OR (iii) it is an operand of an **`ast.And` BoolOp whose other operands include a `NotIn` or a non-constant comparison** (the mixed `"x" not in c or "NEVER" in c` idiom). A **positive-only `ast.And` chain IS evaluated per-operand** (each conjunct is independently pinned-present — e.g. `"audit-enforced gate" in BUILD and "NON-`-D` per ADR-019" in BUILD`, `test_build_slice_skill.py:187-190`; the B-add-1 dominant-conjoined-idiom requirement, preserved for `and`). At `/build-slice` the full `BoolOp`-pin set is machine-classified (positive-only vs excluded) and the count recorded in build-log — not assumed (meta-Critic reservation); verified live: positive-only=10, excluded=20, zero false-positive.
    - **Folded-constant literal extraction** (B3 fix): the searched literal is `ast.Constant.value` of the fully-parsed left operand (CPython folds implicit adjacent-string concatenation at parse time into one `ast.Constant`). Never source-text / first-quoted-token scraping. Operands that are not a single post-fold `ast.Constant` str (f-strings / `ast.JoinedStr` / `%`/`+`/`.format()` built / name-only) are skipped (cannot statically prove absence ⇒ do not flag).
    - **Presence check is against the FULL SKILL.md, not the sub-segment** (B2 fix): a sliced segment narrows *location*, not *presence*; the absent-literal test always runs `literal in full_skill_md_text`. Absent ⇒ violation `stale-skill-prose-pin`.
  - **Sub-form B — risk-status-stale pin** (*git-diff-INDEPENDENT standing invariant* — **revised per /build-slice plan-mode design-wrong deviation**, build-log.md 2026-05-18 00:02). The original git-merge-base-baseline-diff mechanism was inapplicable: `architecture/` is fully gitignored (`.gitignore:11`), so `git show <base>:architecture/risk-register.md` is `fatal` and `git diff --name-only` never surfaces the vault — in the very repo STP-1 must self-apply on (RSAD-1). Revised mechanism: parse the **live** on-disk `architecture/risk-register.md` via the reused `risk_register_audit._parse_risks` (object-identity) → map `R-N` → current `status`. AST-scan `tests/**/*.py` for **`FunctionDef`/`AsyncFunctionDef` names only** (the function-name-token leg — the literal-detection leg is scoped OUT of v1; see "Out-of-scope coverage boundaries"): a stale pin is a test whose function-name matches `(?:^|_)r[_-]?(\d+).*?_(stays|remains|is)_(open|mitigating|retired|accepted)(?:_|$)` (groups → risk-number, verb, claimed-status) AND the live register's `R-<num>` `**Status**:` **≠** the claimed status ⇒ violation `stale-risk-status-pin` naming `R-N`, `claimed → live`, the stale `tests/<file>::<fn>`, remediation. Regex properties (all empirically verified, M-add-1 + targeted-M1 + targeted-M2): **(a)** the `r`-token is `(?:^|_)`-anchored, NOT `\b`-anchored (`\b` is dead adjacent to `_` in snake_case) — so an embedded `r` does **not** false-bind (`test_addr_5_is_open`, `test_parser_4_is_retired` → no match, where the old unanchored form false-matched); **(b)** status is an **explicit alternation** terminated by `(?:_|$)`, not a greedy `(\w+)` + validity-guard — so a descriptive suffix after the status word is still caught (`test_r_4_stays_mitigating_until_spike_done` → `(4, stays, mitigating)`, closing the M2 false-negative); **(c)** still matches the slice-041 precedent `test_r_4_stays_mitigating` → `(4, stays, mitigating)` and the realigned `test_r_4_retired_by_slice_041_…` → no match (no `_(stays|remains|is)_` token). **Per-file AST `SyntaxError` ⇒ skip-with-visible-note, NO violation, NOT exit 2** (ADR-037 / PTFFD-1 discipline — same as the cited `shippability_path_audit.py`/`_pyfn` precedent; a file STP-1 cannot parse for fn-name extraction is the strictly-worse-to-FAIL case ADR-037 already adjudicated, not a fail-closed condition). No baseline, no merge-base, no changed-file set, **no git invocation at all** — the invariant is simply "no test pins `R-N` to a status the live register contradicts." Catches the slice-041 precedent exactly (`test_r_4_stays_mitigating` while live `R-4`=`retired` → `mitigating` ≠ `retired` → fires). A correct in-state pin (`test_r_4_stays_mitigating` while live=`mitigating`; `test_r_4_is_retired` while live=`retired`) → claimed == live → not flagged. (Replaces first-Critic M1 entirely — no git-diff semantics remain — and removes M2's misconfigured-clone-HALT residual: the whole audit is now git-independent.)

## Contracts added or changed

### `tools/state_transition_pin_audit.py` CLI contract
- **Invocation**: `python -m tools.state_transition_pin_audit [--root <repo-root>] [--json]` (default root = ancestor with `.git`). **No `--base`/git-ref arg** — the audit makes no git invocation (2026-05-18 deviation).
- **Defined in code at**: `tools/state_transition_pin_audit.py` (`audit()` + `main()`).
- **Auth model**: N/A (local read-only CLI audit; no subprocess, no network).
- **Exit codes** (sibling-identical triad): `0` clean (incl. when scanned files were skipped-with-note for unparseability) · `1` Important violation (`stale-skill-prose-pin` / `stale-risk-status-pin`) · `2` usage-error — **reserved for hard-input failure only**: `architecture/risk-register.md` unparseable/missing, `tests/` or `skills/` dir missing, repo-root unresolvable. A **per-scanned-file AST `SyntaxError` is NOT exit 2** — it is skip-with-visible-note, no violation (ADR-037/PTFFD-1; targeted-critique B1/B2). Violation `kind`s + `--json` `to_dict()` shape (incl. a `skipped` notes list) mirror `branch_workflow_audit.AuditResult` + `shippability_path_audit` skip-notes.
- **Error cases**: every violation message is attributed + actionable — Sub-form A names `tests/<file>::<fn>` + the missing folded literal (truncated to ≤80 chars) + target SKILL.md + remediation ("realign or supersede this prose-pin in the same fix block"); Sub-form B names risk ID + `claimed → live` status + the stale `tests/<file>::<fn>` + remediation ("realign the test to the live register status or rename off the `_<verb>_<status>` token"). Fail-closed: any register-parse / file-read / AST failure ⇒ exit 2 with an attributed `usage-error`, NEVER a silent exit 0 (R-7/TFFL-1 must-not-defer; the silent-default-off anti-pattern is explicitly forbidden).

## Out-of-scope coverage boundaries (critique M3 — intentional, not accidental)

- The `tests/skill_drift_equality.py::assert_md_forward_synced(in_repo, installed, label=…)` forward-sync drift family binds SKILL.md via `Path` arguments, not `read_file(...)`. It is **deliberately outside** Sub-form A v1: a repointed anchor there fails the EOL-DRIFT-1 content-equality hash (in-repo↔installed), not a prose-pin presence check — that surface is already guarded by its own family. Naming this boundary makes the coverage edge intentional.
- **Sub-form B literal-detection leg** (a status string-literal co-located with a risk-id token inside an assert) is **out of scope for v1** (2026-05-18 deviation refinement): it is materially false-positive-prone (must AST-distinguish a real `assert by_id["R-4"].status == "retired"` from docstring/f-string prose like the `"mitigating"` narrative in `test_r_4_…_retired…:126` and the `{…status!r}` format operand) for a case with **no witnessed instance** — the slice-041 precedent and every real risk-status pin in the corpus is a function-name shape. Adding it now would re-introduce the B1/B-add-1 false-positive class. Recorded as a `/reflect` Discovered follow-up (add only if a non-fn-name risk-status pin is ever witnessed). The fn-name-token leg alone catches the slice-041 precedent and is verified zero-false-positive on the live tree.
- The ADR `accepted`→`superseded` stale-pin sub-form remains out of scope (ADR-047 Decision; no canonical machine-readable test↔superseded-claim signal) — recorded as a `/reflect` Discovered follow-up, not a silent omission.

Non-false-positive guarantees (must-not-defer #3):
- **Sub-form A excludes: own-op `ast.NotIn`; any `ast.Or` BoolOp operand (disjunction — none individually pinned); an `ast.And` BoolOp operand with a `NotIn`/non-constant sibling** (B1 + B-add-1 + Task-1 `Or` refinement) — the 2 live `not in` pins and all `or`-disjunction alternatives (e.g. `"solo-dev" in c or "solo dev" in c`) never fire; positive-only `and` conjunctions ARE checked per-operand (B-add-1 dominant-idiom preserved). Verified zero false-positive on the live repo (exit 0).
- **Sub-form A skips non-constant operands** — f-strings / `ast.JoinedStr` / `%`/`+`/`.format()`-built / name-only (cannot statically prove absence).
- **Sub-form A extracts the folded `ast.Constant.value`** (B3) so implicitly-concatenated multi-line literals (e.g. `test_build_slice_skill.py:162-166`) are searched as their true single value, never a mis-extracted prefix.
- **Sub-form A checks presence against the full SKILL.md text**, never the sliced sub-segment (B2) — slicing narrows location, not presence.
- **Sub-form B `r`-token is `(?:^|_)`-anchored** (targeted-M1) — an embedded `r` (`test_addr_5_is_open`, `test_parser_4_is_retired`) does NOT false-bind a risk-number; verified the old unanchored `re.search` false-matched these and the anchored form does not.
- **Sub-form B status is an explicit alternation `(open|mitigating|retired|accepted)(?:_|$)`** (targeted-M2) — a descriptive suffix after the status word is still caught (`test_r_4_stays_mitigating_until_spike_done` → fires), closing the greedy-`\w+`-suppression false-negative; no separate validity-guard needed.
- **Sub-form B fires only on a claimed≠live mismatch against the live register** — a test whose token matches the live register status is clean; the slice-041 *realigned* name (no verb-token) does not match → clean.
- **Per-scanned-file AST `SyntaxError` is skip-with-visible-note, never exit-2** (targeted-B1/B2; ADR-037/PTFFD-1) — the live `tests/methodology/fixtures/syntax_error.py` (a permanent intentional fixture) is skipped with a rendered note, NOT a fail-closed HALT; exit-2 is reserved for hard-input failure (register/dir/repo-root).
