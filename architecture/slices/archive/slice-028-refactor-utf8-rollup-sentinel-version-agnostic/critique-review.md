## Missed findings

- **B-add-1 (Blocker): AST structural meta-test (template part 2) defeated by helper-extraction (template part 3) — fail-OPEN.** design.md pins the AST meta-test "modeled on slice-014 `test_pmi_1_gate_function_is_version_agnostic_shape`" — which walks the **sentinel FunctionDef body** only (slice-014 pattern at `test_methodology_changelog.py` L666-693). design.md then specifies the failure-path regression test uses "synthetic discovered/covered set injection **via a small extracted helper**." If the discovered/covered computation is extracted into a helper, the real set-building logic moves OUT of the sentinel body the meta-test scans → the meta-test passes trivially even if a future regression smuggles `== N` back into the *extracted helper*. Self-defeating interaction between template part 2 (meta-test scoped to the sentinel FunctionDef) and part 3 (helper extraction). slice-014 did NOT have this hole: its gate function was not refactored to extract a helper; the failure path used `monkeypatch` of `REPO_ROOT` (L731-779), leaving protected logic in-body and in-scan-scope. The design's divergence from precedent (helper-extraction instead of monkeypatch) opens the hole. This is the slice-022 self-violation law firing a *second* layer in (beyond the B2 layer ADR-026 RSAD-1 documents). **Proposed fix**: (a) failure-path test injects synthetic sets via monkeypatch/parametrized fixture of the *in-body* logic (slice-014-faithful — no helper extraction); OR (b) AST meta-test scan scope explicitly widened to include the extracted helper FunctionDef(s) by name AND a counter-anchor meta-test asserts the helper exists and is the one scanned (analogous to slice-014 `test_no_per_version_pmi_1_gate_functions_remain` L696-726). ADR-026 RSAD-1 must confront this as a stated self-defect. Severity **Blocker** — silently neuters one of the three load-bearing template parts; AC#1 becomes structurally unenforced.

- **M-add-1 (Major): covered-set AST walk fail-OPEN on non-`str`-`Constant` list shapes.** design.md / ADR-026 specify covered-set = string elements of `_POSITIONAL_SLICE_TOOLS`/`_ROOT_ONLY_TOOLS` ∪ `_assert_no_encoding_error` second args. Today these are flat module-level `list`-of-`str`-literal assignments (verified L79-97). The design does not pin walk behavior when an element is NOT `Constant(str)` (future `_BASE + ["tools.x"]` BinOp concat, f-string, `Name`, `*splat`). A walk that silently skips non-literal elements drops coverage tokens → uncovered new tool falsely GREEN, defeating AC#2. **Proposed fix**: covered-set AST walk MUST assert every parametrize-list element and every `_assert_no_encoding_error` second arg is `Constant(str)` and FAIL LOUDLY (named diagnostic) on any other node shape — never silently skip. Fail-closed analogue of B1's discovered-set precision. Severity **Major** — real fail-open path but requires a future code-shape change to trigger (not latent in today's tree).

## Severity adjustments

- **B2 post-fix over-claim — SEVERITY-WRONG at the residual, not the finding.** B2 is correctly a Blocker and option-4 direction is right. But post-fix ADR-026 + design.md assert "a name cannot enter covered-set without an executed cp1252 test — parity is observed, not declared" and "a green sentinel *entails* an executed test for every discovered tool." Overstated. AST-reading `_assert_no_encoding_error(proc, "tools.foo")`'s second arg proves only that a string literal textually appears as that arg in a `test_*`-named function — it does NOT entail (i) the subprocess was invoked with `tools.foo`'s argv (copy-paste bug: `proc` ran a different tool, assertion still names `tools.foo`), nor (ii) the test isn't `@pytest.mark.skip`/`xfail`. Genuinely stronger than option-3's free-floating list (must edit a real call site; the parametrize-list direction *is* execution-bound) so NOT a Blocker and does not block — but "observed not declared / entails an executed test" is a *proxy*, same proxy-weakness class ADR-026 rejects option 2 for. Recommend ADR-026 RSAD-1 "Residual watch" state honestly (ADR-013 Consequences-honesty convention, the same M2 was held to) that the bespoke-direction covered-token is a *source-presence* proxy, not an execution observation, and the argv↔assertion-name binding is unverified. File as a tightening of the existing B2 disposition, not a new Blocker.
