# Design: Slice 107 inventory-vault-flip-prose-surface

**Date**: 2026-06-03
**Mode**: Standard

## What's new

- **`tools/vault_flip_prose_inventory.py`** (new) — a deterministic, read-only inventory of `architecture/` + `diagnose-out/` location-literals on the **prose surface** (Markdown), the third vault-flip surface alongside the production + tests surfaces already covered by `tools/vault_flip_readiness_audit.py`. Mirrors that tool's CLI/exit-code/baseline contract; has NO AST to lean on, so classification is line-context-driven (ADR-096).
- **`tests/methodology/test_vault_flip_prose_inventory.py`** (new) — pins the classified baseline, proves the classifier non-vacuous by mutation (AP-5), pins the documented match-residual, and pins the disjointness invariant (the new tool adds no production `must-rewrite` literal).
- A new **`architecture/shippability.md`** row for the prose inventory (RPCD-1/SCPD-1).
- `plugin.yaml` (PMI-1) + `tools/install_audit.py` (INST-1) entries for the new tool.
- Two ADRs: [[ADR-096]] (dedicated standalone prose tool — third surface), [[ADR-097]] (in-tool disposition table resolves `needs-human` without editing prose).

## What's reused

- `tools/vault_flip_readiness_audit.py` — the **model** for the CLI surface, exit-code contract (0 clean / 2 gate / 1 usage), ordered-ruleset classification, line-number-independent multiset baseline, and `--strict` drift gate. NOT modified by this slice (disjoint from the parallel slice-106's `_BASELINE` re-pin).
- `tools/_stdout.py` → `reconfigure_stdout_utf8()` — called first in `main()` (UTF8-STDOUT-1 / AP-8).
- `tools/_vault_paths.py` → `VAULT_ROOT` — the seam for any vault-path the tool itself constructs (see §Disjointness — in practice the tool constructs none, since the prose surface lives at repo-root / under `skills/`, not under `architecture/`).
- Prior decisions: [[ADR-091]] (readiness classification model this mirrors), [[ADR-092]] (the production/tests two-surface split this extends with a third), [[ADR-065]]/[[ADR-085]] (the `VAULT_ROOT` seam).

## Components touched

### `tools/vault_flip_prose_inventory.py` (new)
- **Responsibility**: enumerate every vault-location literal across the prose surface and classify each for the M4 flip (`rewrite-at-flip` | `historical-anchor` | `doc-example` | `needs-human`), fail-closed, with a regression-pinned baseline — so the flip has a complete, drift-guarded prose checklist. Inventory only; rewrites nothing.
- **Taxonomy contract (m1)**: the four class-name string literals `rewrite-at-flip` / `historical-anchor` / `doc-example` / `needs-human` are **deliberately DISTINCT** from `readiness_audit`'s `must-rewrite-before-flip` / `already-seam-routed` / `doc-example-safe` / `needs-human-classification` — the prose surface ≠ the production surface, so a distinct taxonomy is intentional (NOT drift). The `--json` `klass` field, the in-module `_BASELINE`, the test pins, and the M4 checklist all use these exact four strings. (Where this design says "must-rewrite", it is referencing `readiness_audit`'s OWN production class by name — a cross-reference, not the prose tool's class.)
- **Lives at**: `tools/vault_flip_prose_inventory.py` (created by this slice).
- **Key interactions**: reads the prose corpus (filesystem globs below); imports `tools._stdout`; consumed by its methodology test + the shippability catalog + on-demand CLI (the M4 flip operator). No runtime caller in the pipeline loop (a flip-prep tool, like `readiness_audit`).

**Prose surface (scan globs)** — the operational/installed prose that hardcodes the vault *location* for an external reader. Counts are the **boundary-free** `grep -rohE "(architecture|diagnose-out)/"` raw-match counts; because the tool's matcher is now boundary-free (B1), the tool's occurrence count **equals** these (no anchored under-count). The EXACT per-surface numbers are re-derived + pinned by running the built tool (B3):
- `skills/**/SKILL.md` (~292 raw matches)
- `agents/*.md` (~16)
- root `CLAUDE.md` (~7), `INSTALL.md` (~2), `README.md` (~1)
- total = **318** (Builder-executed, all-matches-per-line). **B1/B3 evidence correction (DR-1 M-add / verified by re-execution):** the REAL `readiness_audit._SLASHED_RE` (delimiter class `[\s'"(/=]` — **no backtick**) catches only **69** of the 318; the gap is **249** (216 backtick-wrapped inline-code paths + 32 `)`-preceded + 1 `{`-preceded). The first Critic's "anchored ~285 / gap 33" was reproducible only with a backtick ADDED to the delimiter class (`69 + 216 backtick = 285` exactly) — i.e. the 216 inline-code `` `architecture/…` `` paths are **entirely unmatched** by the real anchored regex, not "matched-but-mis-classified." Boundary-free matching is required to reach all 318; B1 (match) and B2 (classify) therefore overlap on those 216.

Explicitly **excluded** (out of scope — see mission brief): `architecture/**/*.md` (vault-internal prose relocates *with* the vault); the Python production/tests surfaces (already covered by `readiness_audit`).

**Match rule** — a line-text scan (no AST), scanning **all matches per line** via `re.finditer` (NOT a per-line single `re.search` — M-add-1/B3-residue: 24 lines carry >1 match, 32 extra intra-line occurrences; a single-match-per-line scan reports 286 and would FAIL the `== 318` smoke gate). The match is the **boundary-free** form `(?:architecture|diagnose-out)/` — deliberately **NOT** the anchored `readiness_audit._SLASHED_RE` (`(?:^|[\s'"(/=])…`, whose delimiter class has **no backtick**). **B1 correction (Builder-executed against the real corpus, AP-3):** the left-delimiter anchor exists in `readiness_audit` only to avoid matching mid-identifier inside Python *tokens* — a concern that does **not** transfer to free-form prose. On the real corpus the anchored form catches only **69** of 318; the 249-literal gap is dominated by **216 backtick-wrapped inline-code paths** (`` `architecture/…` ``) PLUS 32 `)`-preceded **operational git-pathspecs** in `skills/code-review/SKILL.md:48-57,103` (`:(exclude)architecture/decisions/**`, `:(glob)architecture/*.md`) + 1 `{`-preceded — all of which resolve at runtime and **break at the M4 flip**. Boundary-free matching enumerates them (the pathspecs classify `rewrite-at-flip` via rule 4's pathspec sink — NOT residual). Matching the **slashed** form (not the bare English word `architecture`) is still deliberate — the bare word pervades prose and is not a path. **Documented residual** (the ONLY honest-contract gaps, BOTH enumerated + pinned): (i) a bare `architecture` vault-dir *argument* with no slash — `$PY -m graphify vault architecture` (**7** hits, Builder-verified) — and (ii) the symmetric bare-`diagnose-out` no-slash operational mentions (m-add-1 — `skills/slice/SKILL.md` "consult diagnose-out", `slice-candidates/SKILL.md` "./diagnose-out"; Builder greps `\bdiagnose-out\b` not-followed-by-`/` across the 5 globs and folds operational hits in or confirms empty). Both are enumerated into the in-tool residual list + pinned by `test_bare_vault_dir_arg_residual` (NEVER a silent gap; the residual is the bare-no-slash args ONLY, not the B1 slashed git-pathspec/inline-code classes).

**Classification — ordered ruleset (first applicable wins; every decision LINE/region-anchored per AP-1, never a whole-file substring scan):**
1. **disposition-table override** (highest precedence) — the (relpath, normalized-line-context) is present in the in-tool `_DISPOSITION` table → take its assigned class. This is the [[ADR-097]] mechanism that resolves a `needs-human` literal without editing prose.
2. **fenced-code-block context** — the literal sits inside a ```` ``` ```` fence: an *operational command* fence (line begins with / contains a shell or `$PY`/`python -m`/`cat`/`graphify` invocation resolving the path) → `rewrite-at-flip`; an *illustrative template/example* fence → `doc-example`; a fence the heuristic cannot confidently place → `needs-human` (fail-closed).
3. **historical-anchor markers** on the literal's line — ADR-citation / `archive/slice-` path / changelog `v0.NN.0` ref / the words "historical anchor" / "Glob discoverability" / "supersede(s)" → `historical-anchor` (preserve at flip).
4. **operational literal → `rewrite-at-flip`** — a backticked inline-code `` `architecture/…` ``/`` `diagnose-out/…` `` OR a git-pathspec literal (`:(exclude)`/`:(glob)`/`:(top)` prefix) is `rewrite-at-flip` when its line carries ANY operational signal: an imperative/path-sink verb from the corpus's **actual** vocabulary — `read, run, check, consult, see, open, write, mv, move, update, note, verify, ls, cat, create, delete, rm, append, regenerate` — OR the literal is a git-pathspec, OR the line is a step inside a fenced operational block / numbered markdown step. (**B2/AP-16 fix:** the verb set is the corpus's real operational vocabulary, not a 6-verb subset; the 119 verb-less inline-code paths the Critic measured are NOT silently lost — see rule 6.)
5. **plain non-code prose mention → `doc-example`** — RESERVED for a match in genuine plain prose: NOT inside inline-code backticks, NOT a git-pathspec, carrying no operational signal (cosmetic at worst, never a silent mis-resolve). An **inline-code / fenced / pathspec** literal NEVER defaults here.
6. **fail-closed default → `needs-human` (exit 2)** — every inline-code / fenced / pathspec literal not positively classified by rules 2–4 and not a historical-anchor (rule 3) routes **HERE, not to `doc-example`**. (**B2/AP-12 fix:** this is the backstop that makes the best-effort ruleset SOUND — ambiguity is RESOLVED via the [[ADR-097]] disposition table, never silently re-routed into the non-gating `doc-example` class. On the real corpus this surfaces the ~119 verb-ambiguous inline-code paths for explicit disposition rather than confidently mis-bucketing them.)

> **⚠ Build-time recalibration — AS-BUILT supersedes rules 4–6 above (user-ratified deviation, build-log 2026-06-03 11:16; AP-3 execute-against-real-corpus).** The as-designed rules 5–6 (inline-code-no-signal → `needs-human`) were calibrated against the corpus and found mis-calibrated: they produced **124** `needs-human`, but the data showed these are overwhelmingly **live operational references** (`see \`architecture/triage.md\``, `Update \`architecture/_index.md\``), not genuine ambiguities. The shipped classifier (`tools/vault_flip_prose_inventory._classify_match`) therefore **defaults an in-code / fenced / operational vault path to `rewrite-at-flip`** (the dominant live-reference case); `needs-human` fires ONLY for a true conflict (a genuine preserve-marker — "historical anchor" / "Glob discoverability" / "preserved as …" — on a line carrying an *in-code* literal). **B2's GOAL is fully preserved**: an operational path lands ON the M4 checklist (`rewrite-at-flip`), NEVER the off-checklist `doc-example` (the silent-drop B2 closed); `doc-example` stays reserved for genuine plain prose. **As-built distribution: 318 `rewrite-at-flip` / 0 `historical-anchor` / 0 `doc-example` / 0 `needs-human`** (the `/code-review` M1 fix broadened `_OP_VERBS` to cover skill-`description:` frontmatter inflections `Reads`/`Produces`/`Writes`, moving two LIVE operational paths off the non-gating `doc-example` bucket onto the M4 checklist — closing the last B2 residue; every operational prose reference goes stale at flip, so all 318 are `rewrite-at-flip`). The `needs-human` bucket + the [[ADR-097]] `_DISPOSITION` table remain the fail-closed mechanism (exercised by `test_anchor_plus_incode_routes_needs_human_exit_2` + the disposition unit tests; available for future drift), but the current corpus needs no overrides (`_DISPOSITION = ()`).

**Baseline + drift gate** — the baseline is the sorted multiset of `(relpath, normalized-literal, klass)` for `rewrite-at-flip` + `needs-human`, duplicates included, **line-number-independent / count-sensitive** (like `readiness_audit._BASELINE`, ADR-091). **⚠ AS-BUILT (build-log 2026-06-03 11:40, FORCED by AC5/M1):** the multiset is pinned as an **in-module SHA-256** (`_BASELINE_SHA256`), NOT inlined `(path, value, klass)` tuples — 316 slashed-path tuples in `tools/*.py` would be classified `needs-human` by `readiness_audit` (collection-member + `/`), tripping slice-106's baseline. The hash has the identical gate behavior (`--strict` exit 2 on ANY multiset change); the full enumerated inventory is the `--json` output. **PLUS (m2) a pinned per-class total-count floor for all four classes** (incl. `historical-anchor` + `doc-example`) so a silent `rewrite-at-flip → doc-example` demotion — the dangerous direction that drops a real path off the M4 checklist — also trips `--strict`. `--strict` exits 2 on any multiset diff OR any per-class total-count shrink. **Disposition key (M2 + M-add-1):** whitespace-collapsed line text alone COLLIDES both *across* duplicate lines (`architecture/slices/slice-NNN-` recurs 10× in `skills/build-slice/SKILL.md`) AND *within* a single line (`skills/code-review/SKILL.md:103` carries **5** distinct `architecture/` matches needing different classes — a `:(glob)architecture/*.md` pathspec alongside prose mentions; 24 lines corpus-wide carry >1 match). So the `_DISPOSITION` key is the 5-tuple **`(relpath, normalized-line-context, fence-state, ordinal-among-identical-lines, column-offset)`** — fence-state (in/out of a ``` fence) + the ordinal among identical-text lines disambiguate *cross-line* duplicates (M2), and **column-offset** (the match's start column) disambiguates *intra-line* multi-matches (M-add-1). Two pins: `test_no_ambiguous_duplicate` (no two same-key occurrences need different classes) AND `test_no_intra_line_ambiguous_multimatch` (no single line carries two matches needing different classes without distinct column-offset keys — `code-review.md:103` is the canonical fixture). The two identity models compose — disposition assigns per-occurrence klass, the baseline aggregates.

**CLI**: `--json` / `--strict` / `--repo-root`; exit 0 (clean: no `needs-human` and, under `--strict`, no baseline drift) / 2 (gate) / 1 (usage error). `reconfigure_stdout_utf8()` first.

## Disjointness from the parallel slice-106 (load-bearing)

Slice-106 modifies `tools/project_frame_synth.py` + re-pins `tools/vault_flip_readiness_audit.py::_BASELINE` + `tests/methodology/test_vault_flip_readiness_audit.py`. Slice-107 touches **none** of those — it adds a *new* tool + *new* test. The only shared files are append-only (`architecture/shippability.md`, `plugin.yaml`, `tools/install_audit.py`, `slice-queue.md`/`_index.md`), where parallel slices coordinate at merge, not at build.

**Self-pollution guard** (must-not-defer): because `readiness_audit` scans `tools/*.py`, it WILL scan this new tool. The new tool's own `architecture`/`diagnose-out` mentions must therefore stay in non-resolving contexts so they classify as `doc-example-safe`, NOT `must-rewrite`/`needs-human` (which would trip slice-106's re-pinned baseline at merge):
- match-target constants as **bare-segment** frozenset members (`{"architecture", "diagnose-out"}` — no slash → `readiness_audit` rule-4 needs `/`, falls through to prose-mention) and/or a **regex** string (`"(?:architecture|diagnose-out)/"` — the `architecture` is followed by `|`, not `/`, so it does not match `readiness_audit._SLASHED_RE`);
- AVOID any bare slashed `"architecture/"` **collection-member** literal in the new tool (rule-4 → `needs-human`, fail-closed → trips the readiness gate).
- The mid-slice smoke gate (`vault_flip_readiness_audit --strict` exits 0) is the live proof this invariant holds.
- **Pre-finish re-check (M1):** the same `vault_flip_readiness_audit --strict` exit-0 check is added to the slice's **pre-finish** gate (not only mid-slice — see mission-brief Pre-finish gate), so a late path-construction edit that slips a `root / "architecture"` (a `/`-BinOp operand → `must-rewrite-before-flip` → lands in `_BASELINE_CLASSES` → trips slice-106's re-pinned baseline) is caught before finish. The mechanical discipline: the new tool references vault dir names ONLY as bare-segment frozenset members or `|`-joined regex source — **never** as a `/`-BinOp operand or `Path(...)`/`.glob(...)` argument. (Critic-verified by executing `readiness_audit.audit_file` on a fixture: `frozenset({"architecture","diagnose-out"})` → `doc-example-safe`; `root / "architecture" / "x"` → `must-rewrite-before-flip`.)

## Decisions made (ADRs)
- [[ADR-096]] — Prose surface gets a dedicated standalone `vault_flip_prose_inventory.py` (the vault-flip *third surface*), not a third branch inside `readiness_audit` — reversibility: **cheap**.
- [[ADR-097]] — `needs-human` on the prose surface is resolved by an in-tool `_DISPOSITION` table keyed on normalized line-context, NOT by editing the prose (prose edits are M4) — reversibility: **cheap**.

**Parallel-coordination risk (M3)**: slice-106 has not yet run `/design-slice`; when it does, max+1 ADR numbering also reaches ADR-096+, so a collision is **likely**, not hypothetical. `ADR-096`/`ADR-097` are referenced **14×** across slice-107's artifacts (design.md, milestone.md, the two ADR files) plus the build's forthcoming code/test pins — a "mechanical rename" that misses one site orphans a `[[ADR-096]]` link (AP-10 / AP-13). Mitigation: **(a) preferred** — reserve ADR-096/097 for slice-107 NOW via cross-session coordination (surfaced at the TRI-1 gate below: the operator directs the slice-106 session to mint ADR-098+), eliminating the collision at the source; **(b) fallback** — if a collision lands at merge, the rename is driven by a **grep-verified enumeration** of every `ADR-09[67]` site (`grep -rn 'ADR-09[67]'` across both worktrees), never a hand sweep (FBCD-1).

## Authorization model for this slice
N/A — read-only local CLI tool; no auth surface, no network, no writes to tracked files (output is stdout/JSON; the only writes are the developer-authored in-module baseline + disposition constants).

## Error model for this slice
Mirrors `readiness_audit` exactly:
- **exit 0** — clean: zero `needs-human`, and (under `--strict`) baseline unchanged.
- **exit 2** — gate: ≥1 `needs-human` OR (`--strict`) baseline drift.
- **exit 1** — usage error: prose-surface root missing, an unreadable source file, or a bad `--repo-root` (fail-visible to stderr, never a silent skip — R-7 class).
No new exception types; an unreadable file surfaces as exit 1 with a stderr message.
