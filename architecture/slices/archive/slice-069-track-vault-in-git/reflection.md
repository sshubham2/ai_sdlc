## Discovered

1. **Bash-quote silent backslash-stripping in Python regex character classes embedded in heredocs** (Phase C of /build-slice). Both double-quoted and single-quoted bash heredocs pass Python source code through a JSON-decode + bash-tokenize pipeline that strips one backslash from `\\` sequences. Result: `r"[\\/]"` regex compiles to `[\/]` (character class with `\` interpreted as redundant escape of `/` → matches `/` ONLY, NOT `\` or `/`). Silent failure mode: the first PII redaction pass appeared to substitute 129 occurrences but only forward-slash paths were touched; the backslash-form `C:\Users\sshub\...` residuals (~125 occurrences) survived. Caught via post-sweep `grep -rE` returning non-zero. Fix: construct regex via `chr(92)*2` (literal 2-backslash sequence) in Python source to avoid the bash-escape interpretation chain. **/critic-calibrate watch-list candidate N=1**: any tool/script using regex backslash-character-class patterns embedded in bash heredocs MUST use `chr(92)` construction or a separate `.py` file. If N=3 cumulative emerges across future slices, propose a Critic-prompt dimension.

2. **`git worktree add <branch>` collision when branch is already checked out elsewhere** (Phase H4). The mission-brief specified `git worktree add ../slice-069-verify slice/069-track-vault-in-git` but the slice branch was already checked out in the current worktree. `git worktree` refuses (`fatal: 'slice/069-track-vault-in-git' is already used by worktree at ...`). Fix: `git worktree add --detach ../slice-069-verify HEAD` (detached HEAD at the slice's WIP commit). Build-log preserves the discovery; `tools/branch_workflow_audit.py` docstring + BRANCH-2 entry in methodology-changelog do NOT codify this for future N=4-style verification slices. **Slice-070+ bundle nomination** — small mechanical addition: document the `--detach HEAD` pattern as the canonical N=4 throwaway-worktree verification shape.

## Lessons for next slice

1. **For methodology-revision slices that mint a new mechanism** (any new pathspec / regex / git-mechanic / audit-rule that itself executes at runtime), perform EMPIRICAL EXECUTION of the minted mechanism on a known input BEFORE declaring the rule done at /build-slice Phase B. The slice's own /code-review hop is the structural backstop, but catching at /build-slice is N-1 cheaper.

2. **For slices that document patterns as redactable** (PII patterns, regex strings, secret formats), the documentation surface ITSELF becomes a recursive-self-application surface — the build-log Events naming the patterns by literal value is a leak. Use placeholder forms in the documentation OR redact post-hoc during /validate-slice (as this slice did via tail-pass).

3. **For bash-heredoc Python source with backslash patterns**: ALWAYS use `chr(92)` construction or a separate `.py` file invoked via `python <script>.py`. The Claude Code harness's JSON-decode + bash-tokenize pipeline strips one backslash from `\\` sequences in heredocs — both single- and double-quoted. Silent failure mode catches forward-slash form ONLY.

4. **For N=4-style throwaway-worktree empirical verification**: the canonical command shape is `git worktree add --detach <path> HEAD` (NOT `<branch>`), because the slice branch is already checked out in the current worktree. Codify in `tools/branch_workflow_audit.py` docstring at slice-070+ bundle.

5. **For MEPD-1 INCLUDE-posture slices**: paired-pin discipline per BC-PROJ-10 requires BOTH (a) `test_v_0_NN_0_*_entry_present_in_repo` + `test_v_0_NN_0_*_shippability_consumer_propagation` in `tests/methodology/test_methodology_changelog.py` AND (b) a new `architecture/shippability.md` row. The /reflect Step 5.3 (mandatory shippability-row addition) handles (b); (a) is a pre-/reflect obligation that must land at /build-slice. Slice-069 missed (a); deferred to slice-070+ bundle.

6. **For ADR § Reversibility sections that document revert paths**: BC-1's BC-GLOBAL-2 keyword-trigger fires on `git checkout`/`git restore`/`git stash` literals; the rule's actual intent is code-automation, not prose documentation. Until BC-1 gains negative-anchor filtering on `ADR-Reversibility` / `prose-discussion`, expect defer-with-rationale escalations on revert-discussing ADRs. The slice's own code-Critic m6 finding extends this: now that M5 INCLUDE admits build-log.md to /code-review scope, build-log §Discovered prose mentioning these literals creates a recursively-emergent false-positive surface.

7. **/critic-calibrate probe narrowing** (per Must-not-defer #11): the gitignored-vault probe scope narrows from `architecture/` (now tracked) to `diagnose-out/` + `graphify-out/` (still gitignored).
