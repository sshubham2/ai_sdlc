# Critique: Slice 110 flip-vault-to-external-store

**Critic reviewed**: mission-brief.md, design.md, project-frame.md, new ADRs (ADR-099, ADR-100)
**Date**: 2026-06-04
**Result**: BLOCKED

## Summary

The git-mechanics foundation is sound (shared `$GIT_COMMON_DIR` config, the `_vault_paths` seam, `_vault_write` CAS, the diagnose-out scope-out), but three load-bearing claims fail under empirical execution: (1) the test-breakage scope is materially understated — the Critic measured **~30 genuine in-process tier-2 breakers in the methodology suite alone** (plus ~7 in `tests/skills/`), already at/past the design's "~7 + up to ~30" ceiling and over the ~20 tripwire, so the "1 slice / 1 day" framing is unsound; (2) AC3's "distinct PCR-RETIRE signal / no resolver change" is contradicted by the code — the RETIRE result is signal-**indistinguishable** from a genuine UNKNOWN and exits 1, which the current `/commit-slice` routes to **SOAD-1 manual conflict resolution**, the exact spurious-manual path AC3 exists to kill; (3) the self-referential bootstrap is broken — `/reflect`'s archive step is a literal in-tree `mv architecture/...` (not VAULT_ROOT-routed, invisible to the readiness audit) that will **fail** once the in-tree `architecture/` is removed, and the fix is deferred to slice-111 which runs *after* slice-110's own `/reflect`.

## Findings

### Blockers (must address before /build-slice)

#### B1: Test-breakage scope is empirically understated; the ~20 tripwire will trip → the "1 slice" framing is unsound
- **Claim under review**: mission-brief Scope note — "Static estimate: ~7 hard breakers + up to ~30 more"; the ~20 tripwire. design.md — "only the in-process repo_root=tmp callers genuinely break."
- **Issue**: The Critic executed the flip mechanism (absolute `VAULT_ROOT`) against the suite. The **methodology suite alone produced 74 failures**; subtracting subprocess env-leak artifacts (tmp-repo subprocesses that under real tier-2 resolve their own config-less common-dir → will NOT break post-flip), the **genuine in-process breaker subset is ~30** — and that is from only 7 of the **11 production tools** that compose `X / VAULT_ROOT`. `tests/skills/` added 7 more. The genuine count is already at/over the design's ceiling AND the ~20 tripwire, BEFORE the other 4 tools. The mechanism is exactly as design.md states (`supersede_audit.py:173 slices_dir = project_root / VAULT_ROOT / "slices"` — absolute VAULT_ROOT discards `project_root`), but the *magnitude* is wrong: asserted, not measured.
- **Evidence**: `AI_SDLC_VAULT_ROOT=<ext> $PY -m pytest tests/methodology/` → `74 failed, 1351 passed`; the pure-in-process audit subset → `30 failed, 76 passed`; `tests/skills/` → `7 failed`. Baseline (no override) → `1425 passed, 0 failed`. 11 `/ VAULT_ROOT` tools: critique_review_prerequisite_audit, cross_spec_parity_audit, drift_check_audit, index_router_thinness_audit, parallel_conflict_resolver, project_frame_synth, pulse_worktree_resolver, slice_queue_writer, state_transition_pin_audit, stranded_slice_audit, supersede_audit.
- **Proposed fix**: Do not enter `/build-slice` with the current scope framing. Either (a) **re-scope to a multi-slice plan up front** — a reversible prep slice repoints the ~37 in-process tests to be vault-location-agnostic (green pre- AND post-flip), then a tiny flip slice; OR (b) state the measured number as the *expected* breaker set and pre-commit to the split. The current framing presents a near-certain split as a low-probability tripwire.
- **Builder draft**: **ACCEPTED → ESCALATE to redesign.** The Critic measured what I flagged as "statically unpredictable" — ~37 in-process breakers, exceeding the tripwire. A red suite cannot merge, so ALL breakers must be repointed before the flip can land; the repoints (made location-agnostic) pass pre- AND post-flip, so they belong in a **reversible prep-first slice**. Recommend re-scoping slice-110 → prep-first split (the option declined at /design-slice Q3, now empirically forced). Surfacing at TRI-1 for user re-scope ratification.

#### B2: AC3 — the RETIRE result is signal-indistinguishable from genuine UNKNOWN and exits 1 → current /commit-slice routes it to SOAD-1 manual resolution, not a clean no-op
- **Claim under review**: AC3 / ADR-100 — "a **distinct PCR-RETIRE signal**"; design.md — "already RETIREs when external … No resolver change."
- **Issue**: `_retire_if_vault_external` (parallel_conflict_resolver.py:307–343) returns `action="STOP", conflict_class=ConflictClass.UNKNOWN`. The CLI exit mapping (:2393–2394) is `UNKNOWN → return 1`. So the RETIRE serializes as **exit 1 + action=STOP + conflict_class=UNKNOWN** — byte-identical in `action`/`conflict_class`/exit-code to a *genuine* UNKNOWN. The only discriminator is the `reason` prose substring. The current `/commit-slice` (SKILL.md:198) routes `exit 1 (UNKNOWN)` to *"print stderr verbatim AND fall through to the SOAD-1 3-option block"* — a spurious **manual conflict-resolution prompt**, precisely what AC3/ADR-089 exist to eliminate. ADR-100's "branch BEFORE the dispatch" cannot be done cleanly with "no resolver change."
- **Evidence**: parallel_conflict_resolver.py:331–343 (RETIRE `conflict_class=UNKNOWN`); :2393–2394 (UNKNOWN→exit 1); SKILL.md:198 (`exit 1` → SOAD-1). test_slice_098_vault_routing.py:213–216 pins only `action=="STOP" and "external" in reason` — no skill-consumable discriminator.
- **Proposed fix**: This IS a resolver change, contra design.md. Add a distinct machine-branchable signal: `action="RETIRE"` (or sentinel `external_retire=True`) AND a distinct CLI exit code (exit 0 with `action="RETIRE"` — RETIRE is a clean no-op, not a failure), then branch in SKILL.md on that BEFORE the UNKNOWN→SOAD-1 leg. Correct ADR-100 ("no resolver change" is false), re-sync OSDG-1, and have the AC3 test exercise the full CLI→skill path (assert genuine-UNKNOWN still routes to SOAD-1).
- **Builder draft**: **ACCEPTED-PENDING** (in the flip slice). The "no resolver change / distinct signal already exists" claim is withdrawn — the Critic read the code and is correct (`conflict_class=UNKNOWN`+exit-1 collides with genuine UNKNOWN). The flip slice's design will add `action="RETIRE"`+exit-0 to the resolver, branch `/commit-slice` on it before the UNKNOWN→SOAD-1 leg, correct ADR-100, re-sync OSDG-1, and APED-1-test the full CLI path. This is a fresh instance of **AP-15** (a guard's signal must be a distinct structural property, not a prose-substring proxy).

#### B3: Self-referential bootstrap break — /reflect's archive step is a literal in-tree `mv architecture/...` that fails post-flip, and the prose fix is deferred to the next slice
- **Claim under review**: design.md §Self-referential bootstrap — "post-flip /validate-slice + /reflect write directly to external via VAULT_ROOT. The folder converges in the external store." mission-brief — "the 318-site prose rewrite is deferred to slice-111."
- **Issue**: `/reflect` Step 6 (skills/reflect/SKILL.md:320) is a literal shell op: `mv architecture/slices/slice-NNN-<name>/ architecture/slices/archive/`. NOT VAULT_ROOT-routed. After the in-tree `architecture/` is removed, this `mv` source path **does not exist in-tree** (the slice folder lives in the external store), so the archive step **fails** when slice-110 runs its own `/reflect`. The literal is **invisible to `vault_flip_readiness_audit`** — the audit scans `skills/**/*.py` (:502), NOT `SKILL.md` prose — so the AC2 green-gate gives false assurance the in-loop skills survive the flip. `vault_edit`-routed writes (`_index.md` regen) DO route correctly; the break is specifically the *folder move*. The fix is the slice-111 deferral — but slice-111 runs *after* slice-110's own `/reflect`, so slice-110 cannot complete its own pipeline cleanly.
- **Evidence**: skills/reflect/SKILL.md:320 (literal `mv architecture/...`); vault_flip_readiness_audit.py:488–507 (scans `.py` only); `/commit-slice` reads the slice folder via in-tree `architecture/slices/archive/...` paths (SKILL.md:45,110) that also miss the external folder.
- **Proposed fix**: Either (a) **pull the minimal in-loop-skill prose fixes into the prep slice** — `/reflect` Step 6 archive `mv` (route via `$VAULT_ROOT`/`vault_edit`) + `/commit-slice`'s slice-folder Read paths — since these are on the flip slice's OWN completion path; OR (b) sequence the flip slice's own /reflect+/commit-slice PRE-flip. Extend `vault_flip_readiness_audit` (or a new check) to scan SKILL.md prose for literal in-tree `architecture/` shell ops (the `.py`-only scope structurally misses this class).
- **Builder draft**: **ACCEPTED** → resolved by the re-scope. The prep slice (B1) will route `/reflect` Step 6 + `/commit-slice` folder reads through `VAULT_ROOT`/`vault_edit` AND extend the readiness audit to scan SKILL.md for literal in-tree `architecture/` shell ops — all BEFORE the flip, so the flip slice's successor pipeline completes cleanly. This is the single strongest argument that the prep work MUST precede the move (you cannot flip-then-reflect when reflect itself is unflipped). Fresh **AP-13** (consumer-driven contract: a relocated artifact orphans every by-name in-tree reader — enumerate + repoint ALL, including SKILL.md prose, not just `.py`).

### Majors (address this slice)

#### M1: Rollback ordering + untracked-artifact handling underspecified; "byte-faithful" rests on an unstated EOL precondition
- **Issue**: (a) **Ordering** — `git rm --cached -r architecture` stages deletion; the reverse (`git reset HEAD architecture`) only restores *index* entries and requires the working-tree files already present. So "restore from external copy" MUST precede `git reset`; the design lists them in that order but doesn't call out the hard dependency. (b) **Untracked slice-110 artifacts** — ADR-099/100 + the slice folder are currently `??` untracked; `git rm --cached` never staged them, so rollback recovers them ONLY if the copy-back copies the *whole* external dir, not just the 1033 originally-tracked files. (c) **EOL** — `.gitattributes` pins only `architecture/slice-queue.md` (+ skills/agents) to LF; the other 1032 vault files are NOT normalized → CRLF on disk under autocrlf. "LF-preserving" is the wrong description; a byte-faithful copy preserves on-disk EOL (likely CRLF), which the `_vault_write` CAS compare tolerates (EOL-agnostic).
- **Evidence**: `.gitattributes` (only `architecture/slice-queue.md text eol=lf` for vault); `git status` → `?? architecture/decisions/ADR-099…`; `_vault_write._detect_eol`/`_normalize_eol`.
- **Proposed fix**: Ordered numbered rollback (copy-back THEN reset, with a "working-tree count == tracked count" guard); copy-back copies the entire external store; correct step 2 to "byte-faithful (hash-verified) — preserves on-disk EOL (may be CRLF); CAS compare is EOL-agnostic" and drop "LF-preserving." Rollback-proven-first asserts a per-file **hash** round-trip, not just "passes."
- **Builder draft**: **ACCEPTED-PENDING** (flip slice). All three sub-points correct. The flip slice's rollback runbook will be an ordered, hash-verified, whole-store round-trip with the count guard, and the EOL wording corrected.

#### M2: AC2 readiness-gate cleanliness gives false flip-safety assurance — the gate is blind to the actual breaker class
- **Issue**: The audit exits **0** with **166 `test-update-at-flip`** + 49 `test-collection-pathspec` (`needs_human=0`, `must-rewrite=0`) — the gate (:601–605) trips only on `needs_human`/`--strict`. So AC2's "gate is clean" is honest about the audit but the audit is structurally blind to the genuine breaker class (B1 in-process breakers, B3 SKILL.md prose). Passing it is necessary but nowhere near sufficient. Pairing "green suite, not zero test-update" with "the audit gate is clean" risks the operator treating the clean gate as flip-readiness proof.
- **Evidence**: `vault_flip_readiness_audit --json` → `{must-rewrite:0, needs-human:0, test-update-at-flip:166, test-collection-pathspec:49}`, exit 0; gate logic :601–605.
- **Proposed fix**: Reword AC2 so the **green full suite run with the real tier-2 config active** is the binding gate; demote audit cleanliness to "necessary-not-sufficient pre-check."
- **Builder draft**: **ACCEPTED-PENDING** (flip slice). AC2 reworded: green full-suite-with-flip-LIVE is binding; readiness-audit cleanliness is an explicit necessary-not-sufficient pre-check.
