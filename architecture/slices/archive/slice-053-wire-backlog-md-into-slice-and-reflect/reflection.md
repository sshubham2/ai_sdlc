- **Multi-site-literal contrast clarification** (build-time, N=1): T1/T4/T7/T8 of the 8 mid-slice smoke gate contrasts initially returned `FAIL-TO-FAIL` (rc=0 instead of rc!=0 under perturbation) because the contrast script defaulted to `count=1` (replace single occurrence) but the canonical literals appeared 2-3 times each in the bullet/section. Python's `str.in` substring check only fails when the literal disappears entirely from the section, not when one site is mutated. Resolution: T1/T4/T7/T8 use `count=-1` (replace ALL occurrences); T2/T3/T5/T6 (single-occurrence literals) use `count=1`. This is a build-time clarification of the audit's semantic, NOT a design defect — design.md§"Genuine-contrast proof method" accurately describes a 6-step recipe that works once the perturbation `count` parameter matches the literal occurrence count. Documented in build-log.md DEVIATION + validation.md "Reality surprises". Lesson for future audit-module slices: when authoring anchor-presence audits with canonical literals that may appear at >1 site, EITHER use the all-sites perturbation parameter OR design the literal to be unique-per-section.

## Lessons for next slice

1. **Multi-site-literal contrast handling**: when authoring an anchor-presence audit with canonical literals that may appear at >1 site in the scoped section, the M3 6-step recipe's perturbation step MUST use `count=-1` (all-occurrences) for those literals OR the audit must use a uniquely-positioned variant (e.g., a position-anchored prose that appears at exactly one place). Failing to match the perturbation `count` to literal occurrence count produces silent FAIL-TO-FAIL contrasts that mask audit correctness. Document inline in the audit module's docstring + in the design.md§"Genuine-contrast proof method" subsection.

2. **Use stable-leading-literal anchors for numbered-list items**: markdown linters/formatters may auto-renumber numbered list items mid-build, breaking numeric-prefix anchors (`7. **Foo**`). Use the leading inline literal (`**Foo**`) WITHOUT the numeric prefix in audit constants — robust to renumber pressure. The slice-053 build-time fix (audit constant `_SLICE_SOURCE_7_ANCHOR = "**Diagnose-out backlog**"`) is the reusable shape.

3. **`grep -cF` for known-literal verification**: any verification step that asserts a known-literal substring is present in a file should use `grep -cF` (fixed-string mode), NOT bare `grep -c` (BRE — backslash-escape semantics confuse the count). Especially for literals containing `\d`, `\w`, `{N}`, or similar regex-special characters.

4. **BCR-1 self-bootstrap is correct by design**: this reflection.md is the first dogfood of the new BCR-1 round-trip contract. The trigger correctly no-ops on slice-053 itself (no `**Closes:** SC-` sentinel in mission-brief.md or reflection.md). slice-054 SC-001 fix-pyproject-toml-version-drift WILL carry the literal `**Closes:** SC-001` sentinel and will be the first concrete `Addressed:` annotation appended to `diagnose-out/backlog.md`. The semantic of "mentioned vs closed" disambiguation via sentinel header is now load-bearing — any future slice author writing a mission-brief that mentions `SC-NNN` IDs as documentation context must NOT use a `**Closes:**` prefix unless the slice actually closes those candidates.

5. **`/diagnose → /slice → /reflect` loop is structurally closed; the human-judgement axis closure is now an explicit `/critic-calibrate` candidate (R-14 Residual axis 1)**: BCR-1 closes the deterministic axis. The empirical failure mode that minted slice-053 (Claude self-demonstrating the missing-wire by ranking candidates from internal pipeline signals alone) cannot recur on the deterministic side — the BCR-1 anchor-presence audit FAILs if the consume directive is silently dropped. But Claude reading the now-pinned SKILL.md prose could still elect not to consult `backlog.md`. Per BC-PROJ-10 (slice-052 N=2 missed-by-both-Critics class), this is the human-judgement axis.
