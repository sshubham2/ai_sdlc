## Discovered

- **Python 3.12+ SyntaxWarning on literal `\-` (or any unrecognized escape sequence) inside docstrings.** When a docstring's prose contains a literal regex character-class fragment like `[—\-]`, Python 3.12+'s string-literal-escape-validation parses `\-` as a non-recognized escape sequence and raises `SyntaxWarning`. By default it doesn't fail tests; `-W error::SyntaxWarning` promotes it to a failure. **Generic Python lesson** — applies to any slice that adds string-literal regex patterns or docstring prose mentioning regex syntax. Surfaced this slice at /build-slice T8; deviation rephrased to drop the literal escape sequence. **Possible BC-1 promotion candidate** — the pattern is broader than this slice (every Python-touching slice could hit it); promotion would help future slices avoid the same trap. Watch list for confirmation if it recurs in slice-005+.
- **Cross-cutting-conformance Critic-miss class hardens to N=4 distinct slices.** Pattern: slice-001 (environmental/runtime + tooling-conformance), slice-002 (methodology-conformance + tooling-conformance — fixed THIS slice), slice-003 (testing-discipline-conformance + tooling-conformance), slice-004 (testing-discipline-conformance via "R-NN doesn't match `R-?\d+`" empirical-verification gap + language-conformance via Python 3.12+ docstring escape-sequence). The 9th Critic dimension proposal in slice-003's reflection now has 4 distinct evidence points across 4 slices; sub-clauses (methodology-audit conformance, tooling-doc-vs-implementation parity, BC-1 trigger-keyword false-positive anticipation, TF-1 PENDING→WRITTEN-FAILING genuineness, runtime-environment assumptions, language-version conformance) are all firing. **`/critic-calibrate` skill prerequisite is ≥5 archived slices**; we're at 4 archived, deferring as agreed at slice-003.
- **BC-1 trigger-keyword false-positive recurs — N=2.** Slice-003 deferred BC-PROJ-2 + BC-GLOBAL-1 (LLM-fence-parsing rules) on the "parse" keyword (mission-brief mentioned `tomllib`-parses / `ast`-parses); slice-004 deferred the SAME 2 rules with the SAME rationale (regex/TOML-parsing context, semantically unrelated to LLM fences). - **B1 catch quantified the cost of empirical verification at design-time.** Slice-004's design originally claimed `## R-NN — title` matched `_RISK_HEADING_RE`. Empirical verification at /critique time (one Python one-liner) showed it doesn't — `R-NN` letters fail `R-?\d+` digit anchor. Without the Critic's verification, the slice would have failed at /build-slice T5 first run; the failure mode would have been confusing ("my test extracts `## R-NN — title` and it should match — why doesn't it?"). The cost of ad-hoc empirical verification is ~30 seconds; the savings is the entire slice's time + interpretive overhead. **Generic discipline lesson**: when a design.md claims an example matches a regex/parser/contract, run the example through that parser LITERALLY before accepting the design. Slice-001 and slice-003 both had similar cases (cwd-mismatch tool-denial assumption; argparse exit-code-2 collision). N=3 across 4 slices.

## Lessons for next slice

- **Avoid literal `\-` (or any unrecognized escape sequence) inside Python docstrings on Python 3.12+.** Either escape with `\\-` (faithful, visually noisy), use a raw docstring `r"""..."""` (impractical for multi-purpose docs), or rephrase to drop the literal escape (cleanest). Generic Python lesson; possible BC-1 promotion candidate if it recurs in slice-005+.
- **Empirical verification at design-time costs ~30 seconds and saves entire slice cycles.** When a design.md claims an example matches a regex/parser/contract, run the example through that parser LITERALLY before accepting the design. The Critic now does this as a habit (B1 catch this slice); the Builder should too at /design-slice time.
- **Voluntary Critic on cross-cutting low-tier slices is now N=4/4 paid off, and 2 of 4 caught design-stage failures that would have failed at build time** (slice-003's TF-1 false-PASS warning + slice-004's B1 fatal catch). Default heuristic continues to apply.
- **"Validate using your own ship" pattern is N=2 stable.** Future audit-shipping slices should run /validate-slice's Step 5b VAL-1 with the slice's own new flags/conventions to demonstrate self-consistency. Slice-003 invented; slice-004 reused; pattern is now a stable practice.
