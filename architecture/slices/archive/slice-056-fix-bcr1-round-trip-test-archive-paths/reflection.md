## Discovered

- **Doc-comment-vs-audit-literal self-detection class** (N=1, build-time-reachable, gate-caught at mid-slice smoke): when authoring in-code documentation for a literal-pattern audit, the comment text containing the matched literal verbatim creates circular self-detection (audit greps for the pattern; comment is part of the file the audit scans). Rule for next slice: paraphrase the matched literal in comments — describe the pattern without including it verbatim. Watch-list `/critic-calibrate` candidate (track if N=2 emerges; build-time mid-slice smoke IS the structural backstop per slice-037 law).
- **BC-PROJ-7 scope extends to literal `|` inside backtick-fenced code spans inside markdown cell Description text** (N=1 build-time-reachable, gate-caught at pre-finish SCMD-1 audit): the SCMD-1 audit parser uses naive `inner.split("|")` and does NOT honor markdown `\|` escapes — even pipes inside backtick-fenced code spans (e.g., `Path | None = None`) shift columns. Existing BC-PROJ-7 rule already mandates "pipe-free shippability rows"; this is a scope clarification not a new rule. Build-time gate (SCMD-1 + shippability runner) ARE the structural backstop. Pattern for next slice: scan shippability row Description text for any `|` (including inside code spans) before committing.
- **Whole-file regex needed for multi-line literal-path scans** (N=1 build-time-reachable, gate-caught at corpus backstop test): Python `\s*` matches newlines by default, but per-line `for line in text.splitlines()` iteration misses constructions split across multiple lines. The canonical pattern is `re.finditer(text)` + `text.count("\n", 0, m.start()) + 1` for line numbers. Codified inline in `test_resolve_slice_dir.py::test_no_new_archive_fragile_literals_in_methodology_corpus` docstring + this discovery; no separate vault update needed.
- **Meta-Critic's PROPOSED FIX mechanism needs Builder empirical verification before adoption** (N=1, slice-056 /critique-review M-add-1): the meta-Critic correctly identified the TF-1 AC-numbering miss (finding VALIDATED) but its proposed fix option (a) — "split body AC into `4a./4b./4c.`" — was WRONG at the regex layer (`_AC_ITEM_RE` rejects `4a.`). Builder verified empirically and chose the actual valid fix (multi-row-per-AC). Generalization: Builder recompute-don't-trust discipline (slice-032/034/041/042/049 N≥5) extends to meta-Critic's PROPOSED FIX mechanisms, not just first-Critic ACCEPTED-FIXED edits and not just the underlying finding. Watch-list candidate (if recurs at N=2, codify).
