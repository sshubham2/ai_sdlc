# ADR-088: Close skill-driven RMW vault writes via compare-and-swap

## Context

R-32 (concurrent-write lost-update on a shared mutable vault) has three writer sub-classes. [[ADR-086]] (slice-094, VWS-1) closed the Python-writer class; [[ADR-087]] (slice-095, SVW-1) closed the skill-driven **append** class and *deliberately deferred* the skill-driven **read-modify-write (RMW)** class — `_index.md` recent-10/Active/lessons regenerations (`/reflect`, `/archive`, `/supersede-slice`) and in-place risk-register status flips. SVW-1 marks those 9 sites `<!-- vault-write-safe: deferred-rmw -->` (a sanctioned exemption reason) and `vault_edit` ships `append` only, because "`safe_write_text` is torn-write-safe but NOT lost-update-safe for a read-modify-write" and "the lock cannot span an LLM read+edit+write" (`tools/vault_edit.py` docstring; ADR-087 §Consequences).

The deferral was assigned to "the flip slice" with the hard mandate: *"the flip slice MUST close the RMW class BEFORE the flip goes live — it is not optional polish"* (slice-095 design.md §51). The external-vault flip is LARGE and being split; this slice is the dedicated pre-flip close of the RMW class, so the flip itself reduces to physical-move mechanics.

The obstacle is real: a sidecar lock cannot be held across an unbounded LLM read→think→edit→write turn. The mechanism must prevent *silent* lost-update without holding a lock across that turn.

## Options considered

1. **Held vault-lease** — acquire a lease at skill start, hold across the LLM edit, release at skill end (the slice-095 design's "e.g. a held vault-lease" example). Pro: simple serialization; edits apply in order. Con: holds a lock across an unbounded LLM turn; a dead/aborted/crashed session **strands the lease**, requiring expiry + steal + recovery machinery — a brand-new failure mode on the very integrity path we are hardening.
2. **Structured per-op transforms** — the LLM authors only content (a recent-10 row, a status value); a tool applies the placement (prepend+truncate / set-field / mark-superseded) in-process under the lock. Pro: both concurrent writers' rows land, no retry. Con: 5+ bespoke transforms to build + APED-1-test, AND `/archive`'s **full** `_index.md` regeneration (rebuild from all slice folders) does not fit a prepend/set-field shape → it would *still* need a CAS path → building both exceeds a 1-day slice.
3. **Compare-and-swap (optimistic concurrency by base-comparison)** — a `vault_edit rewrite` subcommand re-reads the target *under the lock* and writes only if its bytes still equal the base the skill read; on mismatch, fail closed (a distinct exit code) and the skill re-reads + re-applies (bounded retry). Pro: ONE uniform mechanism covering targeted edits AND `/archive` full-regen; holds no lock across the LLM turn; fail-VISIBLE (R-7); minimal new code (a base-compare precondition inside `safe_write_text`'s existing lock); clean non-vacuous proof. Con: a truly-concurrent edit costs one retry round-trip.

## Decision

Adopt **Option 3 — compare-and-swap**. Add `tools/_vault_write.safe_rewrite_text(path, text, *, expected_base)` — `safe_write_text`'s temp-write + atomic `os.replace` + bounded-EPERM-retry body, gated by a base-equality check performed *inside* the same `_file_lock`. **The comparison is EOL-NORMALIZED, not byte-exact, and the write PRESERVES the target's existing EOL (critique B1):** the RMW targets (`_index.md` 309KB, `risk-register.md` 137KB) are CRLF on disk — `.gitattributes` does not normalize `architecture/**` and slice-033/[[ADR-033]] explicitly scopes whole-vault renormalization OUT — so a byte-exact compare against an LF base would false-conflict every attempt (channel unusable on the very files R-32 exists for), and an LF write would churn CRLF→LF (EOL corruption on an unguarded surface). `safe_rewrite_text` reads current raw bytes, compares `_normalize_eol(current) == _normalize_eol(expected_base)`, and on a match writes `text` re-applied to the target's detected EOL; mismatch → `StaleVaultBaseError`. **`_normalize_eol` maps CRLF→LF ONLY — trailing newlines and all other bytes are preserved verbatim (critique-review M-add-1)** — so a concurrent trailing-newline truncation is a genuine UNEQUAL → conflict, never a silent MATCH/overwrite (the dangerous direction), while a pure CRLF↔LF representation flip is EQUAL → no false-conflict. The base is captured tool-mediated (a `vault_edit read`/snapshot emitting raw bytes; `--base-file` read in binary, NOT the `Read` tool's formatted output — critique M2). Expose as `vault_edit rewrite --file <vault-rel> --base-file <base> (--content-file <new> | --stdin)`, exit **0** written / **2** usage / **3** CAS-conflict (the retryable signal; bounded by `_REWRITE_RETRY_MAX`). The 9 `deferred-rmw` skill sites route through it (a genuinely-append-shaped site routes through the existing `vault_edit append`). The SVW-1 audit (`tools/skill_vault_write_safety_audit.py`) gains `vault_edit rewrite` as a route token, becomes **op-class-aware (critique B2)** — a rewrite-class directive verb citing only an `append`-class token is a channel-mismatch VIOLATION, with a documented lexical-ceiling residual (mirroring the M2/R-2 honest-scope note). **The bare `tools.vault_edit` token is RETIRED as a standalone clean signal (critique-review B-add-1)** — a route reference must NAME its subcommand (`vault_edit append` / `vault_edit rewrite`) for the op-class match to be sound, else the flat-OR first-hit-wins loop would clean a rewrite site via the bare substring regardless of subcommand; an adversarial positive (`$PY -m tools.vault_edit append` on a regenerate verb → VIOLATION) proves the bare-token path is severed. The audit also **removes `deferred-rmw` from `_EXEMPT_REASONS`** (a lingering marker becomes an `unknown-exemption-reason` VIOLATION — the deferral is un-re-claimable), and drops the 3 `deferred-rmw` allowlist rows (registered total 12→3, `project-open-single-shot` only).

The lock genuinely spans read→compare→write in-process; the LLM's read+edit occurs outside the lock, but the under-lock CAS re-validation converts a stale-base overwrite from **silent lost-update** to **detected + fail-closed**. Concurrent writers converge: A commits; B's base-compare fails → B re-reads (sees A's change) → re-applies → commits. Both updates land.

## Consequences

- **R-32's third and final write-safety sub-class closes.** With VWS-1 (Python) + SVW-1-append + this (SVW-1-RMW), the entire write/append/rewrite axis is enforced on both paths. R-32 stays **`mitigating`** — it retires only at the flip's physical move/git-untrack (the silent-corruption hazard is a property of the shared mutable store, which does not exist pre-flip; every shared-aggregate file is still git-tracked + PCR-mediated today, [[ADR-066]]). The residual-to-retirement narrows to *flip mechanics only* — no open write-safety sub-class remains.
- **SVW-1's enforced scope tightens** (the `deferred-rmw` escape hatch is retired) without minting a new RULE-ID — this completes SVW-1's documented-as-deferred half. MEPD-1 **EXCLUDE**: no new tool module, no PMI-1 fan-out, no VERSION/changelog mint (mirrors the N≥8 risk-narrowing tool-extension lineage; also avoids the MCFS-1/AVFS-1/TVFS-1 forward-sync fan-out = R-28-contention-optimal).
- **Skill prose gains a retry branch** (read → `vault_edit rewrite` → on exit-3 re-read + retry, bounded). `/reflect`, `/archive`, `/supersede-slice` SKILL.md change; `reflect` is OSDG-1-guarded so its install forward-syncs (before this slice's own `/reflect` runs).
- **Honest residual unchanged**: SVW-1 remains a static prose audit; it cannot enforce runtime obedience (the R-2 class, [[ADR-029]]). The CAS channel is safe *when used*; obedience rests on the cooperative model ([[ADR-067]]).

## Reversibility

**Cheap.** `safe_rewrite_text` is an additive function; `vault_edit rewrite` an additive subcommand; the audit change is a route-token add + an enum/allowlist trim. Reverting (re-adding `deferred-rmw` to the enum + re-marking the sites) is a small mechanical edit — no data migration, no contract consumer beyond the three skills' prose. The CAS protocol itself is local and stateless (no persisted lease/sequence to unwind).
