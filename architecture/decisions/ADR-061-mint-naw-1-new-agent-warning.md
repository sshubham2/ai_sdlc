# ADR-061: Mint NAW-1 (New-Agent Warning)

## Context

R-18 (`risk-register.md:299-316`, slice-061-discovered) — **Newly-installed Claude Code subagents are not hot-loaded into the running session**: the agent registry is built at session start; mid-session writes to `~/.claude/agents/*.md` are invisible to `Agent(subagent_type=…)` calls until the user restarts Claude Code. Any slice (N+1) running in the SAME session as a prior slice (N) that shipped a new subagent → an `Agent` spawn for that new subagent at N+1 raises `Agent type '…' not found`.

**Class-signal cumulative N=2**:
1. **slice-061** (N=1, witnessed): slice-060 shipped `/code-review` and the `code-review` subagent; the same Claude Code session running slice-061 hit `Agent type 'code-review' not found` at `/code-review` auto-advance — see `architecture/slices/archive/slice-061-fix-install-python-detection-and-prompt-fallback/reflection.md:78-82` + R-18 §Mitigation paragraph. User-ratified deferral via SOAD-1 structured options.
2. **slice-062** (N=2, predicted-then-confirmed): slice-062's reflection L40 explicitly predicted recurrence ("R-18 N=2 cumulative recurrence on slice-060 N+1 governed-slice axis — predicted by slice-061 reflection L82, empirically confirmed this slice"); the recurrence happened at slice-062's own `/code-review` auto-advance and was disposed identically — user-ratified skip with `code-review.md` documenting `Result: AGENT-UNSPAWNABLE`.

slice-062 reflection L40 + L78 promotes R-18 from watch-list to **active slice-063 mitigation nomination** and enumerates three candidate fix classes (re-numbered here per the slice-062 reflection's verbatim numbering to match this ADR):

1. **Fix (a) — methodology-side warning** (cheapest + most generalizable, per slice-061 reflection L26): `/build-slice` Step 6 emits a WARN naming the session-restart-before-next-slice recommendation when the slice diff includes a new `agents/*.md`. Same shape as BCI-1's reflect-step deterministic-downstream-gate pattern (slice-030A): for a non-deterministic upstream step ("the user remembers to restart Claude Code after a new-agent slice ships"), the sound control is a deterministic downstream gate that surfaces the fact mechanically.
2. **Fix (b) — `/code-review` error-semantic widening**: extend `/code-review` SKILL Step 2's existing `agent-unspawnable` handler from "exit 1 HALT" → "WARN + auto-advance with `Result: AGENT-UNSPAWNABLE` documented" specifically when the agent file exists on disk AND in the prior-slice diff. Codifies the slice-061/slice-062 user-ratified disposition declaratively.
3. **Fix (c) — Claude Code platform fix**: registry hot-reload on agent-file-write. Out-of-scope for the AI SDLC methodology (lives in the Claude Code platform codebase).

**Why a new rule, not an extension of an existing rule**: NAW-1 is structurally NEW behavior — there is no existing rule whose coverage set NAW-1 extends. The closest analogues (BCI-1, MCFS-1, AVFS-1, TVFS-1) are all *forward-sync gates* for version-bearing artifacts; NAW-1 is a *discovery gate* for a session-runtime side-effect of a slice's content. It does not "extend the forward-sync family." It mints a new mechanism on the discovery-gate axis. Per the slice-062 reflection L77 Inclusion-heuristic discipline ("new mechanism = bump-required + new ADR; voluntary-restraint-zero-bump-zero-ADR is RESERVED for retirement-discharge / part-(b) closure shapes"), NAW-1 takes the **mint a new RULE-ID** path — naming-class peer of CRSI-1 (slice-060), TVFS-1 (slice-059), PVFS-1 (slice-054), AVFS-1 (slice-050).

**Why a standalone tool, not a pytest assertion**: this sits on the **discovery-gate** side, not the forward-sync side, so the AVFS-1/MCFS-1/TVFS-1 tool-vs-pytest rationale (out-of-repo runtime read) does NOT apply directly. But the read IS a `subprocess.run(["git", "diff", ...])` call against an environment-mutable mutating-state surface (the slice's branch vs the default branch) — structurally closer to TVFS-1's `importlib.metadata` read than to PVFS-1's pure pyproject.toml read. A standalone tool also matches the existing Step 6 gate-list shape (BRANCH-1 / BC-1 / PMI-1 / UTF8-STDOUT-1 / CRP-1 / PCA-1 / BCI-1 / MCFS-1 / STP-1 / AVFS-1 / TVFS-1 — every Step 6 gate is a `tools/*.py` invocation), preserving call-site uniformity. The "pytest assertion as gate" precedent (PVFS-1, ADR-056) was chosen only when the read is purely in-repo file content; NAW-1's git-diff-against-base read is closer to the runtime-metadata class. Route C (standalone tool) is chosen.

## Options considered

1. **Route A — Fix (a) only via standalone tool, NAW-1 minted** *(chosen)*:
   - **Pros**: Cheapest deployable mitigation matching the slice-062 reflection's "cheapest + most generalizable" framing; tool-bearing call-site parity with the Step 6 gate family; mints a discoverable RULE-ID so the mechanism is findable from the changelog + risk-register; non-blocking-by-construction (exit 0 on both detection branches) so it cannot mis-fire as a slice-regression signal.
   - **Cons**: New `tools/*.py` module → BC-PROJ-9 multi-surface fan-out (plugin.yaml + install_audit._CANONICAL_TOOLS + INSTALL.md tool-count ×2 + test_utf8_stdout _ROOT_ONLY_TOOLS + shippability row). Marginal cost: ~6 fan-out edits, all routine + audit-gated.
   - **Chosen because**: directly implements the slice-062 reflection L40 explicit candidate (a); strongest cost/benefit on the slice-063 candidates ranked at /slice; closes R-18's full causal chain (the runtime cache-miss class is methodology-discoverable + user-actionable BEFORE the next slice's chain runs).

2. **Route B — Fix (b) instead: widen `/code-review` SKILL.md `agent-unspawnable` error-semantic**:
   - **Pros**: Locally cheaper (one SKILL.md edit, no new tool, no PMI-1 fan-out). Codifies the user-ratified disposition declaratively so the prompt doesn't fire again per-incident.
   - **Cons**: Narrower — only covers the `/code-review`-specific manifestation of R-18; future agent-shipping slices that wire their new agent through some other Skill+Agent path (e.g., a hypothetical `/critique-v3` minting a new critique-v3 agent) would still hit the cache-miss without surfacing. Doesn't surface the fact to the user at `/build-slice` Step 6 — only at the *next* slice's `/code-review` auto-advance, which is too late (the user already started the next session/slice). Misses the "warn BEFORE the next slice's chain runs" property the slice-062 reflection L40 names as the value of fix (a).
   - **Rejected because**: narrower mitigation surface AND later detection point. Fix (b) remains a viable slice-064+ defense-in-depth addition on top of NAW-1, but is not the right primary R-18 fix.

3. **Route C — Fix (c): wait for Claude Code platform to add registry hot-reload**:
   - **Pros**: Eliminates the root cause; no methodology-side surface needed.
   - **Cons**: Outside this project's control; no ETA; would still leave the methodology unable to detect the failure mode if a similar runtime-cache class appears elsewhere (a fix-(a)-shaped mechanism is generalizable to any "session-runtime cache for an artifact a slice writes" class).
   - **Rejected because**: not actionable from this codebase; platform-fix waits don't gate methodology slices.

4. **Route D — voluntary-restraint: mint no new rule, just add an undocumented WARN in `/build-slice` SKILL.md prose**:
   - **Pros**: Cheapest of all (one SKILL.md prose addition).
   - **Cons**: Violates the slice-062 reflection L77 voluntary-restraint discipline boundary — that posture is RESERVED for retirement-discharge / part-(b) closure shapes (slice-037/046/050/052/055/056/057/061 N=8 cumulative). NAW-1 is a structurally-new mechanism, not a retirement-discharge — applying voluntary-restraint here would silently re-open the slice-049 "drift-guard member-addition is a methodology-surface behavior change" lineage that ADR-051 explicitly closed.
   - **Rejected because**: misapplies the voluntary-restraint discipline to a new-mechanism slice; would skip the changelog + ADR + bump shape that the slice-049/050/051/057/058/059/062 N=6 cumulative extends-not-mints precedent (and slice-050/054/059/060 N=4 new-RULE-ID precedent) collectively codify.

## Decision

Mint **NAW-1 (New-Agent Warning)** as a new methodology-class rule-ID via **Route A** (standalone tool + Step 6 wiring).

**Gate**: new standalone tool `tools/new_agent_warning_audit.py` — a structural sibling of `tools/ai_sdlc_tools_version_forward_sync.py` (TVFS-1, slice-059) at the CLI + dataclass + exit-contract layer, with the read-mechanism specialized to "added `agents/*.md` files in the slice's git diff vs the default branch":

- **CLI**: `--root` (repo root; default = two parents up from this file, AVFS-1/MCFS-1/TVFS-1 convention), `--check` (default action), `--json` (machine-readable output). No positional slice arg (the audit operates on whole-repo diff state, not a single slice folder — same shape as TVFS-1).
- **Read mechanism (B1 critique fix)**: a **union of three `git`-derived sources** covering all states a new agent file can occupy at `/build-slice` Step 6 — slice work lives in the **uncommitted working tree** at Step 6 (commits land only at `/commit-slice`, the LAST step, user-invoked post-`/reflect`); `git diff <base>...HEAD` alone is commit-vs-commit only (per [git-scm.com/docs/git-diff](https://git-scm.com/docs/git-diff) "`<commit>...<commit>` … starting at a common ancestor of both") and would return EMPTY for an uncommitted new agent — defeating the audit's purpose (tautologically green for every real new-agent slice). The three sources:
  1. `subprocess.run(["git", "diff", "--name-only", "--diff-filter=A", base, "--", "agents/*.md"], …)` — **working-tree-vs-base**; covers modified + staged-but-uncommitted additions (no `..HEAD` suffix → working-tree-aware comparison).
  2. `subprocess.run(["git", "ls-files", "--others", "--exclude-standard", "--", "agents/*.md"], …)` — **untracked-new** agent files (the canonical untracked-file enumerator per [git-scm.com/docs/git-ls-files](https://git-scm.com/docs/git-ls-files)).
  3. `subprocess.run(["git", "diff", "--name-only", "--diff-filter=A", f"{base}...HEAD", "--", "agents/*.md"], …)` — **commits-vs-base**; covers already-committed-in-branch agents (e.g., a `/build-slice` Step 4 intermediate commit or a worktree-add path).

  The three result sets are unioned and deduplicated by path. `base` is resolved via BRANCH-1's `_resolve_default_branch` logic at `tools/branch_workflow_audit.py:127-146` — `git symbolic-ref refs/remotes/origin/HEAD` → `git config init.defaultBranch` → **`None`** (M3 critique fix: there is NO `main` fallback in the implementation; `None` → `_resolve_added_agent_files` returns `usage` and NAW-1 exits 2 per BRANCH-1's `default-branch-unresolvable` semantics at L329-341).

  **Worked example** (B1 critique fix): a `/build-slice` Step 6 dry-run on a slice that has written `agents/foo.md` (untracked) to disk but not yet committed reproduces a WARN via source (ii). A slice that ran `git add agents/foo.md` but not `git commit` reproduces a WARN via source (i). A slice with a `feat()` commit already attached to `slice/NNN-…` carrying `agents/foo.md` reproduces a WARN via source (iii). All three states surface the same WARN text to the user.
- **Exit contract** (binary; intentionally narrower than AVFS-1/TVFS-1's tri-state — there is no "drift" branch for a discovery gate):
  - `0` synced (no added `agents/*.md`) — quiet stdout in `--check` mode; structured `status: "clean"` in `--json`.
  - `0` warn (≥1 added `agents/*.md`) — WARN line(s) on stdout naming each new agent path + session-restart-before-next-slice instruction + R-18 cross-reference; structured `status: "warn"` + populated `warnings:` list in `--json`.
  - `2` usage error — repo root unresolvable, `git` unavailable, `git diff` errors (non-zero exit), or default-branch resolution fails. Distinct stderr message.
  - **No exit 1** — by construction. A new-agent slice is not a slice regression; the WARN is informational, never a HALT.
- **`tools._stdout` UTF-8 convention**: `main()`'s first executable statement is `_stdout.reconfigure_stdout_utf8()` per UTF8-STDOUT-1 (slice-022).

**Attributed WARN message** (template, anchored in this ADR for the `tests/methodology/test_new_agent_warning_audit.py::test_warn_line_cites_agent_path_session_restart_and_r_18` substring-pin):

> NAW-1 NEW-AGENT WARNING — this slice adds the subagent file `{agent_path}`. The Claude Code agent registry is loaded at session start; the new agent is NOT visible to `Agent(subagent_type=…)` calls in this session. Before invoking the next slice's chain, restart Claude Code so the new agent is loaded. See `architecture/risk-register.md` R-18. This is a WARN, not a slice regression.

**Wiring** (1 point; intentionally NOT mirrored at `/reflect` Step 5b — see Consequences):

- `/build-slice` Step 6 pre-finish — non-opt-out, runs every slice; appended after the TVFS-1 gate. The Step 6 checklist gains: `[ ] **New-agent session-restart warning (NAW-1)** — see "New-agent warning audit" below`.

**No `/reflect` Step 5b counterpart**. NAW-1 is structurally distinct from AVFS-1/MCFS-1/TVFS-1: those are forward-sync gates whose installed-side mutation needs a `/reflect` Step 5b ungated re-verification (the R-7/slice-022 silent-disable class for rule-promotion-gated steps). NAW-1 has no installed-side mutation — the warning is single-shot at `/build-slice` Step 6 with no parallel state to verify at `/reflect`. Adding a `/reflect` Step 5b-naw would be cargo-cult parity, not a real gate.

**Atomic version bump shape**: **5-part PMI-1** + the BC-PROJ-9 multi-surface fan-out for adding a new `tools/*.py` module. The 5 version-bearing legs are: `VERSION` + `plugin.yaml.version` + `pyproject.toml [project].version` (PVFS-1) + `## v0.66.0` methodology-changelog header + installed `~/.claude/ai-sdlc-VERSION` (AVFS-1 forward-sync). The BC-PROJ-9 inventory fan-out adds 6 sites: `tools/install_audit.py` `_CANONICAL_TOOLS` (new module name inserted alphabetically — between `tools.methodology_changelog_forward_sync` and `tools.mock_budget_lint`); `tests/methodology/test_utf8_stdout_regression.py` `_ROOT_ONLY_TOOLS` (new entry appended); `plugin.yaml` (new `tools/` path entry inserted alphabetically); `INSTALL.md` two hard-coded "27 executable methodology tools" literals (L22 + L166) → "28"; `architecture/shippability.md` new row #63 (BCR-1-traceability axis cites BOTH NAW-1 AND R-18); installed `~/.claude/methodology-changelog.md` (MCFS-1 forward-sync — automatic when in-repo changelog is bumped); installed venv `ai-sdlc-tools` `pip install --upgrade .` refresh (TVFS-1 bootstrap for the 28-tool inventory).

**Bootstrap (slice-063 only)**: NAW-1 is conditional-bootstrap-clean. The audit runs at slice-063's own Step 6 against slice-063's own diff. slice-063 does NOT add any file under `agents/*.md` (the slice ships a `tools/*.py` audit + `skills/build-slice/SKILL.md` edit + `architecture/risk-register.md` flip; zero `agents/*.md` deltas). Therefore slice-063's own Step 6 NAW-1 invocation exits 0 quietly — vacuous-pass — which is the structural self-application discharge. Every slice after 063 inherits a self-gating NAW-1.

Mints a new rule. Supersedes nothing. Sits on the **discovery-gate** axis adjacent to (but not extending) the forward-sync family (PMI-1 / PVFS-1 / AVFS-1 / MCFS-1 / TVFS-1).
