# Risk Register

Active risks discovered during slice work. Each entry follows the **RR-1** schema (`tools/risk_register_audit.py`): H2 heading `## R-1 — <title>` (em-dash separator, canonical; single hyphen `-` also accepted; double-hyphen `--` is NOT accepted — the regex is single-character), with required fields **Likelihood**, **Impact**, **Status**, plus optional **Reversibility**, **Discovered**, **Mitigation**, **Notes**. Free-form prose may follow the field block — the audit's parser ignores it (its `_FIELD_RE` regex is single-line, walks until non-field-pattern content begins).

`/reflect` appends new entries on Discovery. `/risk-spike` retires risks. `/slice` reads via `tools.risk_register_audit` to rank risk-first slice candidates by Score = Likelihood × Impact.

## R-1 — Cwd-mismatch tool denial for spawned subagents in /diagnose

**Likelihood**: medium
**Impact**: high
**Status**: mitigating
**Reversibility**: cheap
**Discovered**: slice-001-diagnose-orchestration-fix (2026-05-09)
**Mitigation**: slice-029 (ADR-027) makes `/diagnose` Step-5 pass dispatch **sequential by default** — one `Agent` call per message — which defeats the parallel-spawn permission cascade-failure mode ([claude-code #57037](https://github.com/anthropics/claude-code/issues/57037)) on the default path. Status is `mitigating`, **not `retired`**: (1) R-1's independent cwd-mismatch hypothesis (see the causal-attribution caveat below) is untouched by dispatch sequencing; (2) the `/diagnose --parallel` opt-in path retains the original parallel-spawn exposure by the caller's explicit choice. Escalation to `retired` requires both conditions cleared (cwd-mismatch hypothesis disproven or independently fixed AND the parallel path removed/proven-safe).

When `/diagnose` is invoked with a TARGET path that is *outside* the parent thread's current working directory, spawned `general-purpose` subagents lose Read / Grep / Bash / PowerShell access entirely. Only `Glob` remains. Symptom: 1 of 4 launched subagents (Sonnet, 03a-dead-code) gave up; 3 of 4 (Opus, 01-intent / 02-architecture / 03b-duplicates) improvised with filename-only signal but produced degraded analyses (e.g., 03b returned honest-empty findings because it couldn't read function bodies).

**Impact in practice**: /diagnose run from outside TARGET cwd produces a degraded `diagnosis.html` — passes that depend on code Read or graphify Bash (most of them) cannot perform their analysis. Slice-001's orchestration *itself* handles this correctly (degraded-pass `.failed.raw` artifact, fence parser still works), but the analysis quality is lost.

**Workaround (current)**: invoke `/diagnose` from inside the target's cwd (`cd <TARGET> && /diagnose`). The skill's default-to-PWD behavior in Step 1 already supports this. Slice-002 (2026-05-09) adds an explicit Step 1 cwd-mismatch warning so the user is alerted when they invoke with an out-of-cwd TARGET.

**Causal-attribution caveat (per slice-002 critique M1)**: cwd-mismatch is one *hypothesis* for the symptom, not confirmed root cause. An alternative hypothesis is **parallel-spawn permission cascade-failure** documented at [claude-code GitHub #57037](https://github.com/anthropics/claude-code/issues/57037), which fires when multiple Agent tool calls dispatch in one message — exactly what /diagnose Step 5 does. Related issues: #18950 (subagents don't inherit user-level permissions), #37730 (subagents prompt for already-allowed tools). The two hypotheses aren't mutually exclusive; controlled experiment needed to disambiguate.

**Fix candidates** (slice-002 picks documented-constraint as cheapest):
1. Documented constraint — add the cwd-must-match note to `/diagnose` SKILL.md Step 1 + an at-runtime check that warns when explicit-path TARGET differs from cwd. **Implemented in slice-002**.
2. Orchestrator pre-cd — `cd $TARGET` before spawning subagents. Untested whether subagent permissions follow.
3. Parent-thread pre-compute — graphify queries + reachability tables + file listings + code excerpts pre-computed in parent and embedded in subagent prompts. Removes subagent tool dependency entirely. Bigger change. Would also defeat the parallel-spawn cascade-failure mode (only one Agent call dispatched at a time, with all data pre-embedded).

## R-3 — Graphify symbol-resolution may conflate same-name cross-file symbols into phantom edges

**Likelihood**: medium
**Impact**: medium
**Status**: mitigating
**Reversibility**: cheap
**Discovered**: slice-019-harden-diagnose-layering-evidence (2026-05-13)

Graphify's symbol-resolution apparently collapses cross-file same-name symbol references (e.g., two files independently defining `enum NodeType` — a parallel type file pattern common in monorepos with backend + frontend) into a single graph node, creating phantom import edges between them. Witnessed at `/diagnose` F-LAYER-bca9c001 false-positive: graphify-out reported "45 frontend files import src/workflow/adapters/types.ts" when zero frontend files textually import from `src/`; the actual pattern was 17 frontend files importing `NodeType` from a *parallel* frontend-local `frontend/lib/workflow/types.ts` (537 LOC, hand-maintained copy with identically-named enums).

**Impact in practice**: medium — wherever a graphify consumer interprets edges as import-edges without textual verification, the same false-positive class can fire. `/diagnose` 03f-layering is the witnessed instance; other passes (`02-architecture` "where the code disagrees" references, `03d-half-wired` UI↔backend edge detection, `03e-contradictions` graphify shortest_path consumers) MAY also be theoretically exposed but no instance has been observed yet. Other consumers (`/architect`, `/validate`, `/discuss`, `/sprint-runner`, `/codebase-analysis`, etc.) are theoretically exposed; no evidence of impact in those yet.

**Mitigation (in place)**: slice-019 codifies LAYER-EVID-1 at the `/diagnose` 03f-layering pass-template level — subagent MUST grep-verify imports before HIGH-severity emission. This closes the witnessed false-positive class at the consumer layer rather than the graphify layer. Status: `mitigating` (not `retired`) because the root cause in graphify is untouched.

**Escalation criteria**: if `/critic-calibrate` flags additional symbol-conflation false-positives in other `/diagnose` passes OR in other graphify consumers (N≥2 distinct slices reporting similar phantom-edge issues), promote a follow-on slice to either (a) extend LAYER-EVID-1 to those passes or (b) fix graphify symbol-resolution upstream. Choice (b) is reversibility=cheap at the graphify code level but has broad blast radius (all graphify consumers); choice (a) replicates the LAYER-EVID-1 surgical pattern per affected consumer. The fix surface choice is documented in ADR-017.

**Notes**: ADR-017 (slice-019) is the design decision; LAYER-EVID-1 (methodology-changelog v0.33.0) is the codified rule. R-3 is the explicit tracker for the broader-class concern beyond the witness pass.

## R-2 — No programmatic test ensures /diagnose emits cwd-mismatch warning at runtime

**Likelihood**: medium
**Impact**: low
**Status**: open
**Reversibility**: cheap
**Discovered**: slice-002-fix-diagnose-contract-and-cwd-mismatch (2026-05-09)

The cwd-mismatch warning added in slice-002 is delivered by `SKILL.md` Step 1 prose telling the orchestrator (Claude main thread) to detect TARGET ≠ `$PWD` and emit a warning. The prose-pin tests (`test_skill_md_step1_documents_cwd_constraint`, `test_skill_md_step1_emits_cwd_mismatch_warning`) guard the **prose's existence**, but nothing programmatically verifies the orchestrator actually emits the warning at **runtime**.

Acknowledged-fragile per slice-002 critique M3: the slice's whole point (warn the user about R-1) relies on Claude reliably executing the SKILL.md prose's instruction at runtime. A future regression — orchestrator silently ignoring the warning prose — would not be caught by the unit-test suite; only manual observation during `/validate-slice` AC #5 would surface it.

**Impact in practice**: low — at worst, the warning silently disappears and users invoking with out-of-cwd TARGET get the degraded diagnosis without an early heads-up. Findings quality is the same with or without the warning; the warning's value is purely advisory ("re-invoke after cd'ing for better results"). No correctness, security, or data-integrity implication.

**Fix candidate** (deferred — open R-2): tighten `/validate-slice` AC #5 verification to capture the warning text via prompt instrumentation (sandbox /diagnose invocation, grep for pinned phrase like "WARNING: TARGET resolves to a path outside"). Defer to a future slice if real regressions surface; current cost (manual smoke at /validate-slice AC #5) is acceptable.

## R-7 — TF-1 audit field-line regex silently DISABLES the gate when `**Test-first**: true` carries a trailing annotation

**Likelihood**: medium
**Impact**: medium
**Status**: retired
**Reversibility**: cheap
**Discovered**: slice-031-complete-shippability-decoupling (2026-05-17, at T7/pre-finish — TF-1 reported "not enabled" despite the brief declaring test-first)

**Fix candidate**: `test_first_audit.py` should distinguish "field absent" (default-off, clean) from "field present but value/format unparseable" (→ a loud `malformed-test-first-field` violation, NOT silent default-off). Or relax the regex to accept trailing annotation after `true|false`. Decide at a future methodology-hardening slice. Not slice-031 scope (tooling change → its own slice).
